# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Burrow is an educational x86-64 OS: **assembly boot → C loader → C nucleus → Go kernel**, aiming at a POSIX-like system that runs DOOM. Waves 0-10 are done: boot chain, nucleus core (traps, memory, timer, threads, futexes, SSE), the stock Go 1.27.3 runtime running in ring 0 on the nucleus's Linux-syscall shim, Go drivers (IRQs as wake-ups, PS/2, serial, PCI, ATA, BGA framebuffer) with a console, a file tree (VFS over io/fs: initrd, ramfs, devfs, FAT32), and user processes: static Linux programs (asm, or C with musl) in ring 3 whose syscalls the Go kernel serves, and a Unix on top: fork/execve/wait4, pipes and descriptors, signals, a TTY line discipline with job control, init, and a musl shell with tools. busybox ash runs too, and so does Doom (doomgeneric + Freedoom) on Linux-compatible `/dev/fb0` and `/dev/input/event0`. Wave 12 (ports) is done too: threads, epoll, a Go user program, Lua, C++ and TinyCC compiling C on Burrow; `docs/06-guides/PORTING.md` is the guide. All 12 planned waves are complete, and W13 (a workbench: `vi` and kilo on the screen console, writable FAT32, a persistent `/home`, `make run-dev`; `docs/06-guides/WORKBENCH.md`) too; W14 (desktop groundwork: more RAM, a PS/2 mouse, `select` and the start-up calls, a real-time clock, file `mmap`, Unix sockets with names and `SCM_RIGHTS`, the console's `KD*`/`VT_*` modes; `docs/04-plan/waves/WAVE-14-desktop-groundwork.md`) is done too, and so is W15 (static Qt 6.12 widget programs on `/dev/fb0` with linuxfb and evdev, from a FAT disk at `/opt/qt`; `qtpad` edits `/home` files; `WAVE-15-qt.md`, PORTING.md's Qt section). W16 is done too: an X11 desktop (TinyX `Xfbdev` on `/dev/fb0`, dwm, st on pseudo-terminals, dmenu, Doom in a window; `startx` and `make run-desktop`; `docs/06-guides/DESKTOP.md`, PORTING.md's X11 section, `WAVE-16-x11-desktop.md`). ## Commands

The build targets Linux/WSL (bash, gcc, nasm, qemu, go 1.22+, python3). On this Windows host, run `make` from WSL, not PowerShell. On non-Linux hosts use a cross compiler: `make CC_TARGET=x86_64-elf-gcc LD_TARGET=x86_64-elf-ld OBJCOPY=x86_64-elf-objcopy`.

## Architecture (big picture)

- **Layers and ownership** (`docs/02-architecture/ARCHITECTURE.md`): stage1 (512 B MBR, only loads stage2) → stage2 (A20, E820, manifest, CPUID, protected mode, CRC-verifies the loader, identity paging, long mode, calls loader with `RDI = boot_info`) → loader (freestanding C: reads the `nucleus` ELF via ATA + CRC, copies its segments to phys 1 MiB, builds identity + physmap + W^X nucleus page tables, upgrades boot_info to v2, loads CR3 and jumps with `RDI = physmap + 0x1000`; does not stay resident) → nucleus (`nucleus/`, linked at `0xFFFFFFFF80100000` with `-mcmodel=kernel`, shares `common/` with the loader; *mechanism*: IDT/GDT, PMM/VMM, threads, futexes, syscall gate from W5) → Go kernel (*policy*: drivers, VFS, processes, POSIX).
- **Key trick (ADR-0003):** the Go kernel is a stock `linux/amd64` binary; the nucleus pretends to be a tiny Linux and answers the Go runtime's syscalls. Userland later uses the same Linux ABI via musl. Go never runs interrupt handlers; IRQs become wake-ups (ADR-0005). No allocation in Go on interrupts-off paths.
- **Cross-language contracts** live in `include/burrow/` (`boot_info.h`, `manifest.h`) and are mirrored by hand in `boot/boot_abi.inc`, in `tools/mkimage/manifest.go` and `video.go` (the manifest, the `video` payload) and in `kernel/bootinfo` (boot_info). Changing a struct or fixed address means updating all mirrors plus `docs/02-architecture/MEMORY_MAP.md` / `BOOT_PROTOCOL.md`. C side uses `__attribute__((packed))` + `_Static_assert` on offsets; Go has layout tests (`TestManifestLayoutMatchesC`, `TestVideoLayoutMatchesC`, `TestParseFramebuffer`).
- **Disk layout:** LBA 0 stage1, LBA 1 manifest, LBA 2..33 stage2, then payloads named in the manifest (`loader`, `nucleus` = stripped `build/nucleus.disk.elf`; built by `tools/mkimage`).
- **Loader-chosen addresses** live in `loader/layout.h` (nucleus physical window 1-4 MiB, palloc range up to stage2's 1 GiB identity map, `PHYSMAP_BASE`). Addresses inside boot_info stay physical. Stage2 writes boot_info v1 (`BOOTINFO_VERSION_STAGE2`); the loader writes v2 (`BOOTINFO_VERSION`). CRC32 is computed identically in mkimage (Go), stage2 (asm) and loader (C).
- **Testability via interfaces:** C uses small function-pointer "ops" structs (`common/char_sink.h`, `loader/block_device.h`, `pt_ctx` in `common/paging.h`); pure modules (common/*, loader manifest/memmap/elf64/elf_load/palloc/vmsetup/image, nucleus pmm/regions) include neither `io.h` nor `cpu.h` and are host-tested; `UNIT_SRC` in the Makefile lists them. Inline asm lives only in those two headers.
- **`common/`** holds freestanding code used by both the loader and the nucleus (kprintf, lib_string, crc32, serial, char_sink, io.h, cpu.h). The Makefile compiles each `common/*.c` twice (`build/loader/common_*.o`, `build/nucleus/common_*.o`); every `common/*.c` except `serial.c` is also in the host unit-test build. Go: interfaces in `kernel/hal`, fakes in `kernel/haltest`; real hardware only in `kernel/arch/amd64` behind build tag `burrow`, so everything else builds and tests on the host.
- `snippets/` holds compile-checked reference code (nucleus syscall gate, Go IRQ goroutine); it is not part of the build. The Doom backend graduated to `user/doom/`.

- **Nucleus structure** (`nucleus/main.c` calls each module's init in order, each prints one `[nucleus] ... ok` marker): `boot.c` (boot_info, physmap, modules) → `gdt.c` → `trap.c`/`trap.asm` → `frames.c` (PMM) → `vmm.c` (drops identity map, CR0.WP) → `apic.c` → `time.c` → `fpu.c` → `sched.c` → syscall gate → `irq.c`; then `ktest_run` if a `ktest` boot module exists, else `BURROW:NUCLEUS:OK`. `panic()` in `nucleus/panic.c`; errors are `-errno` with Linux numbers (`nucleus/errno.h`).
- **Trap path:** every vector enters on an IST stack; `trap.asm` copies the `struct trap_frame` onto the current thread's kernel stack (`this_cpu()->kstack_*`, `gs:0`/`gs:8`) so handlers may block or switch threads. Since W20-S05 per-CPU state is behind GS (ADR-0011): `swapgs` on every ring-3 entry (`trap_common` by saved CS, `syscall_entry_user`) and exit (`trap_resume`); LSTAR points at `syscall_entry_user` only while a user thread is current; APs start through `nucleus/ap.asm` at 0x8000 (`smp.c`) and since S06 schedule from the one run queue (`sched.c` switching and blocking, `thread.c` creation; `g_sched_lock` is held across `switch_to` and dropped by the thread switched to; object lock before `g_sched_lock`); since S07 every change to a present page-table entry is shot down on every CPU that may cache it (`tlb.c`; `percpu.cr3`; spinlock loops call `tlb_poll`), and Go and user threads run on any CPU (`main` stays on CPU 0). Faults that are allowed are listed in the `.fixup` section (`nucleus/probe.asm`: `probe_read64/probe_write64/probe_ud2`); `trap_last` records them. Anything else prints `[trap] #XX at rip=...` plus registers and panics.
- **Go kernel (W6):** `kernel/cmd/kernel` is built as a static `GOOS=linux` binary linked at `0x7e0000000000` (`build/kernel.elf`) and shipped only on `build/go.img` as the `kernel` payload; `disk.img` and ktest images stay nucleus-only (fast). `nucleus/go_load.c` maps it and starts thread `go-m0` from a trap frame (`thread_create_from_frame` -> `trap_resume`); `clone` children start the same way with the parent's registers. Every runtime syscall enters `nucleus/syscall.asm` (ring-0 callers classified by RIP in Go or nucleus text, IRETQ back, only RAX/RCX/R11 change) and `nucleus/shim.c`'s table; handlers live in `shim_proc.c`, `shim_mm.c`, `shim_thread.c`, `shim_poll.c` with Linux numbers in `shim.h`. Unknown numbers print `[shim] UNIMPLEMENTED syscall N` once. Nucleus-private calls are `0x1000+` (`NUCLEUS_ABI.md`), reached from Go with `syscall.RawSyscall` (`kernel/arch/amd64/nucleus.go`). Implement each syscall's Linux *semantics* that the runtime relies on (BUG-0009: `MADV_DONTNEED` must zero; `MAP_FIXED` zeroes; futex timeout 0 = do not wait). VM operations hold the address space's `kmutex` (BUG-0008).
- **Go drivers (W7):** interrupts are wake-ups (ADR-0005): ISA lines come through the 8259 in virtual-wire mode (LAPIC LINT0 = ExtINT, so EOI goes to the 8259); `nucleus/irq.c`'s ISR masks the line, EOIs, marks it pending and wakes the one thread in `irq_wait`; `irq_ack` unmasks. Go side: `amd64.IRQ` (`syscall.Syscall`, so the P is handed off) behind `hal.IRQLine`; `driver.Serve` runs wait → handle → ack on a locked OS thread. Drivers live in `kernel/drivers/*`, call `driver.Register` from `init()` and touch hardware only through `driver.Env`; `driver.StartAll` starts them in name order. Keyboard (`drivers/ps2`) and serial (`uart.Input`) bytes go into one channel read by `kernel/console`. Boot order in `kernel/cmd/kernel/main.go`: banner → `testFaults` (kargs) → selftests → drivers → console; `make go-smoke` ends with the console's `poweroff`. A `kargs` boot module's words become the Go kernel's argv (`nucleus/go_load.c`).
- **Files and pixels (W8):** `kernel/vfs` is a mount table over `io/fs` (longest-prefix mounts; writes through `vfs.Writable`); every file system passes `testing/fstest.TestFS` (devfs excepted: `/dev/zero` never ends). Tree at boot (`kernel/cmd/kernel/initrd.go`, `disks.go`): `/` = `fs/tarfs` over the `initrd` boot module (zero copy; `initrd/` in the repo, packed reproducibly by the Makefile), `/tmp` = writable `fs/memfs`, `/dev` = `fs/devfs` (drivers register via `driver.Env.Dev`), `/mnt` = `fs/fat` (FAT32; read-write since W13-S04: `fs/fat/write.go`, `dirwrite.go`, `rename.go`) on `hdb`, or `/home` when the volume's label is `BURROWHOME` (W13-S05, `make run-dev`) = `build/data.img` built from `datadisk/` by `kernel/cmd/mkfat`. Disks are `block.Device`s (`kernel/block`, conformance in `block/blocktest`), named by `drivers/ata` (both IDE channels: hda-hdd since W15-S06; READ MULTIPLE and `rep insw` since W15-S05, BUG-0017; FAT reads runs of clusters at once); the kernel mounts each data disk by its FAT label (`BURROWHOME` /home, `QTDATA` /opt/qt, else /mnt). Go reads boot data with `nu_bootinfo` + `amd64.PhysBytes` and maps device memory with `nu_mmio_map` (`driver.Env.MapMMIO`). `drivers/bga` sets 1024x768x32 (since W21-S03 only when the firmware set no mode) and `kernel/gfx` draws (pitch-aware, PIT-27; any pixel format since W21-S03; hand-drawn 5x8 font in `gfx/font.go`); the console is teed onto the screen (`consoleOut` in `screen.go`); since W13 `gfx.Console` keeps a cell grid and understands a VT100 subset (`gfx/vt.go`), so full-screen programs like `vi` draw on it. `pci.Scan` enumerates once for every driver. Heredocs halve backslashes in this environment: write files with escape sequences via the Write/Edit tools.
- **User processes (W9):** mechanism in the nucleus, policy in Go. `nucleus/uspace.c` (address spaces: a PML4 per process sharing the kernel's upper half; frames come from `nu_page_alloc` and stay Go's) and `nucleus/uthread.c` (ring-3 threads; every user SYSCALL or exception becomes a request `{tid, nr, args}` in a FIFO that Go drains with `nu_syscall_wait` and answers with `nu_syscall_reply` or `nu_uthread_kill`). The gate classifies callers by **CR3** (not the kernel's = user); since W10 it saves a full `trap_frame` (vector `0x100`) and returns through `trap_resume` (IRETQ), and `uthread_return_to_user` turns a non-canonical return RIP into a fault (PIT-24). `kernel/proc`: `Mem` (pages, copyin/copyout through the physmap, never the process's CR3), `LoadELF` (static ET_EXEC / static-PIE; `execve` also runs `#!` scripts since W16-S04, `script.go`), `BuildStack`, `System` (one dispatcher goroutine, a goroutine per request; syscalls in `syscalls.go`/`memcalls.go`, listed in `docs/02-architecture/POSIX_COVERAGE.md`). The nucleus calls sit behind `proc.Nucleus` (`arch/amd64.Nucleus`, `proc/proctest.Fake` for host tests). Programs live in `user/` (`*.asm` via nasm+ld, `*.c` via musl-gcc) and land in the initrd's `/bin`; the console's `run` starts one. Go kernel memory is demand-zero (BUG-0012): commit marks pages `PTE_DISCARDED`, a ring-0 #PF fills them. Go images boot with `GO_MEM ?= 512M` (`MEM` for `smoke.sh`); `nu_page_alloc` keeps 32 MiB for the kernel, and a process that runs out is killed (W14-S01). The dispatcher yields after starting handlers (BUG-0014: a blocking nucleus call keeps Go's only P). W14-S03 added `select`/`pselect6` (`select.go`, over `poll`'s wait loop), `statx` (`stat.go`), the start-up calls (`startcalls.go`), and `kernel/random` behind `getrandom` and `/dev/urandom` (ChaCha8 seeded from RDRAND or the TSC; not for cryptography); `user/startup` runs on the host's Linux and on Burrow in `make ports-smoke`. W14-S04: `drivers/rtc` reads the CMOS clock once at boot and sets the nucleus's wall clock (`nu_set_realtime`), so `CLOCK_REALTIME`, Go's `time.Now` and file dates are real; `kernel/proc/clock.go` has the user clock calls; busybox and dev smokes boot with `FIXED_RTC` (`-rtc base=2030-01-02T03:04:05`). W14-S05: `mmap` of regular files is private (an `area` with an `io.ReaderAt`, filled at first touch; writable `MAP_SHARED` is `-ENODEV`); `user/mmaptest` in `make ports-smoke`. W14-S06: `socketpair` (`kernel/proc/sock.go`, `sockcalls.go`, `sockmsg.go`; stream, datagram, seqpacket), and `write` raises `SIGPIPE` on `EPIPE` (BUG-0015); `user/socktest` runs on the host's Linux and on Burrow in `make ports-smoke`. W14-S07: `socket`/`bind`/`listen`/`connect`/`accept` (`socknames.go`, `sockconn.go`; names in `System.names`, path names are memfs socket nodes via `vfs.MakeSocket`), `SCM_RIGHTS` and `SCM_CREDENTIALS` (`sockmsg.go`); named datagram sockets are `-EOPNOTSUPP`; `user/socknames`. W14-S08: `kernel/vt` keeps the console's keyboard mode (`K_RAW`/`K_MEDIUMRAW`/`K_OFF`, applied to scancodes in `cmd/kernel/vtkeys.go`), display mode (`KD_GRAPHICS` makes `screenOut` stand aside like `/dev/fb0`) and VT mode, each undone when the process that set it exits; `proc/vtcalls.go` answers the `KD*`/`VT_*` ioctls, and `/dev/tty0`/`tty1` open the terminal.
- **A Unix (W10):** the nucleus gives Go a stopped thread's registers (`nu_uthread_regs`, a 672-byte `struct uregs` with FXSAVE; writes are sanitized in `nucleus/uregs.c`), threads from a register image (fork), `set_space` (execve) and `interrupt` (stop at the next return to ring 3, nr `0xFFFF0100`). Only a syscall's answer sets RAX; answered faults and interrupt stops resume. In `kernel/proc`: the process tree and `wait4` (`process.go`), init = PID 1 kept by Go with no thread, reaping orphans (`system.go`), refcounted descriptions and per-fd cloexec (`files.go`), pipes (`pipe.go`), `/tmp` writes (`wfile.go`), the `*at` calls and cwd (`pathcalls.go`), signals with a Linux `rt_sigframe` delivered when a request finishes or on an interrupt stop (`signal.go`, `sigframe.go`), and the terminal calls (`ttycalls.go`) over `kernel/tty` (canonical/raw, ISIG to the foreground group; since W16-S03 also pseudo-terminal pairs, `tty/pty.go` and `proc/ptycalls.go`: `/dev/ptmx`, `/dev/pts/N`, a controlling terminal per process for `/dev/tty`). ioctl requests are their low 32 bits (BUG-0019); a keyboard mode change flushes the console terminal's input (BUG-0020). The console's `sh` runs `user/sh.c` with the terminal's foreground group (`kernel/cmd/kernel/run.go`); go-smoke types a whole shell session (`tests/smoke/keys/boot_to_go.keys`). busybox (W10-S08) is configured by `user/busybox.config` and ships only on `go-busybox.img`; `poll` (`kernel/proc/poll.go`) waits on `Poller` files, and a poller on the terminal counts as a reader.
- **Devices and Doom (W11):** device files speak Linux. A devfs device may offer more than read/write through interfaces `kernel/proc/devices.go` looks for on `Device()`: `Ioctler`, `Mappable` (physical memory for `mmap(MAP_SHARED)`; such pages are never freed and fork shares them, `proc.Mem.MapDevice`) and `Poller` (which also makes `O_NONBLOCK` work); `devfs.Opener` gives each open its own handle. `/dev/fb0` = `kernel/fbdev` over the BGA framebuffer; while it is open the on-screen console clears to black and draws nothing (`screenOut` in `kernel/cmd/kernel/screen.go`), repainting on the last close. `/dev/input/event0` = `kernel/evdev`, fed raw scancodes by the PS/2 driver through `driver.Env.Scancodes`; while open it grabs the keyboard. Since W14-S02 the PS/2 mouse (port 2, IRQ 12, `drivers/ps2/mouse.go`) feeds `driver.Env.Mouse` into `/dev/input/event1` (`evdev.Mouse`) and `/dev/input/mice` (`evdev.Mice`, mousedev's PS/2 stream); both event devices answer `EVIOCGBIT`, which is how toolkits tell them apart. User C programs get the Linux UAPI headers via `build/uapi` (links to the host's `linux-libc-dev`). Doom: `user/doom/doomgeneric_burrow.c` + doomgeneric built by `scripts/doom.sh`, run as `run /bin/doom -iwad /mnt/freedoom1.wad` on `go-doom.img` with the WAD on `doom-data.img`.
- **Threads and ports (W12):** a `Process` has `Thread`s (`kernel/proc/thread.go`): per-thread TID (main = pid), signal mask and pending set, EINTR channel (`t.cancel()`), TLS, sigaltstack, `clear_child_tid`. Syscall handlers that need the caller live in `ttable` as `func(t *Thread, a)`; the rest stay `func(p *Process, a)` in `table`. `clone.go` (threads and the fork shape), `futex.go` (wait queues in Go under one lock), `epoll.go` + `eventfd.go` over `Poller`, `limits.go`. User `mmap`/`brk` memory is demand-zero (`area.go`): a #PF request inside an area is answered by mapping a frame and resuming. Go user programs: `user/go/<name>/main.go` (own module) are built static by the host toolchain into `/bin`. Lock order: `s.mu` before `p.mu`; `futexMu` alone. Downloaded ports (`scripts/ports.sh`) ship on `go-ports.img` with a C sysroot under `/usr` for `tcc -static`.
- **Threads:** `schedule()` must update percpu kstack bounds, TSS.RSP0, FS_BASE, CR3, LSTAR and FXSAVE state before `switch_to` (PIT-22). Blocking primitives use `thread_block_unlock` (PIT-23). The nucleus's C is `-mgeneral-regs-only`; xmm is only touched from asm.

## Test conventions (`docs/05-testing/TEST_STRATEGY.md`)

- **New pure C module:** add `tests/unit/c/test_<mod>.c`, add the module `.c` to `UNIT_SRC` in the Makefile, and declare + `RUN()` every test in `test_main.c` (no auto-registration).
- **Serial markers:** format `[component] message`, success `BURROW:<NAME>:OK`. Expect files (`tests/smoke/expect/*.txt`) are **append-only**; never weaken one to make a test pass. Smoke fails on any `PANIC`/`FAIL` line or out-of-order marker. `make smoke` checks every file in `SMOKE_EXPECT` against the same boot.
- **ktest:** `int kt_<name>(void)` with `KT_CHECK` in `nucleus/ktest_*.c`, declared in `ktest.h`, registered in the table in `ktest.c`, listed in `tests/ktest/<suite>.txt`, with `[ktest] <name> ok` appended to `tests/ktest/expect/<suite>.txt`. Tests that must crash belong in `run_all.sh` via `with_ktest <name>`. Tests that enable interrupts must leave IF as they found it.
- `kprintf` supports only `%% %c %s %d %i %u %x %X %p`, the `0` flag, width and `l`/`ll`/`z`; there is no `-` flag.
- **QEMU's CPU** is `QEMU_CPU ?= Broadwell-noTSX-IBRS` (W20-S02, S03: SMEP and SMAP, which the nucleus switches on; XSAVE and AVX, kept per thread; `kt_smap_smep_user_page` and `kt_avx_state_per_thread` fail without them; `qemu64,+xsave` hangs QEMU 10's TCG).
- **QEMU exit codes:** guest writes `0x10` to port `0xF4` → exit 33 (pass); `0x11` → 35 (fail); 124 = timeout = hang bug. Every failure path must write debug-exit `0x11` so failures are instant.
- **Regression cases:** add a mutator in `tests/regression/run_all.sh` with `case_run REG-NNNN-name "<expected text>" 35 mutator`; use `lba_of <img> <name>` rather than hard-coding payload LBAs. Go kernel crash cases use `with_kargs <word>` (handled in `kernel/cmd/kernel/kargs.go`). Every bug gets a test named after its BUG/REG id.
- **Screen checks:** `tests/smoke/expect/<name>.screen` lists `size`/`pixel` checks of PPMs that a keys file's `screendump <file>` steps save; `smoke.sh` runs `tests/smoke/checkscreen.py` on it. `scripts/ppm2png.py` turns a dump into a PNG to look at.
- **Typing into a boot:** `tests/smoke/smoke.sh <img> <expect> <timeout> <keys-file>` (steps `wait`/`type`/`key` (`key <name> [n]` repeats; a `wait` must not be satisfied by the echo of the line typed before it: split markers in the middle, `do''ne`, BUG-0033), `screen W H` + `abs X Y` for the tablet through QMP (W22-S05), sent with QEMU `sendkey` by `tests/smoke/sendkeys.py`, and `mouse <dx> <dy>` (split into steps of at most 400: QEMU's PS/2 queue is small and merges what does not fit), `click`/`press`/`release <button>` through `mouse_move`/`mouse_button`; the monitor socket lives in `/tmp` because WSL's `/mnt/c` has no Unix sockets).
- **Ring-3 ktests** (`nucleus/ktest_uthread.c`) build a process from hand-assembled machine code and play the Go dispatcher themselves through `nu()` (`ktest_nu.h`).
- **Go drivers:** host-test with `haltest` (`FakePorts`, `FakeIRQ`, `Fake8042`) and `kernel/hostsim`; the on-target proof is a marker in `boot_to_go.txt`.
- **A hang leaves a dump (W20-S01):** when a keys step times out, `sendkeys.py` presses Alt+SysRq, and the kernel prints every process, thread (the syscall it is in) and `kernel/proc` goroutine (`[dump] ...` lines, `proc.System.Dump`) before QEMU is stopped; read those first.
- Smoke logs go to `build/smoke-<name>.log`. They are read as text whatever bytes a program writes (`grep -a`: Qt's linuxfb writes a NUL, W15-S03).

## Coding rules (`docs/06-guides/CODING_STANDARDS.md`)

- Every file starts with a comment: what it does, what it must never do, which doc/ADR explains it. Files < 300 lines, functions < 50.
- Names carry units (`size_bytes`, `count_sectors`, `phys`/`virt` prefixes). No magic numbers outside one constants place per component (`boot_abi.inc`, headers, Go `const` blocks).
- Loader C: C11 freestanding, `-Werror`, `-mgeneral-regs-only` (SSE not enabled), **no mutable initialised globals** (the loader is CRC-verified; see BUG-0003). Hardware access only through `io.h`-style headers.
- Assembly: NASM, document clobbered registers in each routine header, `.name` local labels, constants from `boot_abi.inc`. stage1 has a hard 512-byte budget — check `make sizes`.
- Go: gofmt + go vet clean; errors are values; `panic` only for kernel invariants.

## Workflow (`docs/06-guides/WORKFLOW.md`)

- One slice per commit, message prefixed with the slice id: `W4-S03: load manifest entry with CRC check`. Bug fixes: `BUG-0007: fix ...` with the regression test in the same commit.
- Write the test/marker first and see it fail, then implement.
- Keep the living docs current: `docs/living/DEVLOG.md` (newest first, template at top), `BUGS_AND_MITIGATIONS.md` (every surprise gets a BUG-NNNN; PIT-NN lists anticipated pitfalls per wave), `RISKS.md`. Mark slices `[~]`/`[x]` in the wave file. New design decisions get an ADR from `docs/03-decisions/ADR-0000-template.md`.
