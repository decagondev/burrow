# W23 /proc and virtio Devices  (M23)  — status: in progress
Goal: Burrow looks like Linux to the tools that look inside it, and its disks and network card are the fast paravirtual ones. Demo: busybox `ps`, `top`, `free`, `uptime`, `pidof`, `tty`, `mount` and `df` work on the console and in st; `top` shows a spinning program's CPU time climbing; a Go program finds itself with `os.Executable`; `/home` and the ext2 root live on virtio-blk disks and survive a reboot; busybox `wget` fetches over virtio-net with the address from DHCP; `logger` reaches busybox `syslogd` over a named datagram socket; `make proc-smoke`, `make virtio-smoke` pass; `make test` green. Stories: E20.F01-F06 ([BACKLOG.md](../BACKLOG.md)).

Where we start (after W22): there is no `/proc` at all, so busybox is built without `ps`, `top`, `free`, `mount` and `df` (`user/busybox.config`: "nothing here needs /proc or mount"), busybox's `tty` prints "not a tty" on a pseudo-terminal (musl's `ttyname` reads `/proc/self/fd/N`; W22-S06 had to tell two shells apart by a variable), and Go's `os.Executable` fails (`/proc/self/exe`). Nothing counts CPU time: `getrusage` is all zeros, `wait4` fills no `rusage`, there is no `times`, and `sysinfo` has memory (`nu_mem_info`) and uptime but a load average of 0. Processes live in `kernel/proc` (`System`, `Process`, `Thread`; lock order `s.mu` before `p.mu`), with argv kept only on the user stack. The VFS (`kernel/vfs`) is a mount table over `io/fs` with links (`vfs.Resolve`, W19-S05) and one walker behind `kernel/proc/lookup.go`. Disks are IDE (`drivers/ata`, PIO with READ MULTIPLE, hda-hdd) behind `block.Device` (conformance in `block/blocktest`), mounted by label (`disks.go`). The network card is the e1000 behind `netdev.Device`, with addresses fixed in `/etc/net.conf` ("No DHCP yet", `netstack/config.go`). W22 built a pure, host-tested virtio 1.0 PCI transport (`kernel/virtio`: capabilities, negotiation, split queues in DMA pages) and shared interrupt lines (`driver.Lines`) for the tablet, saying block and network devices would use it next. Named datagram Unix sockets are `-EOPNOTSUPP` (W14-S07, E14.F08).

Design (policy in Go; the nucleus only gains a CPU-time counter):
- **`/proc` is a file system over the process table.** `kernel/procfs` is an `io/fs.FS` (passes `fstest.TestFS` against a fake) built over a small `procfs.Source` interface that `proc.System` implements; it never imports `kernel/proc`. Each read takes a snapshot under the usual locks (`s.mu`, then each `p.mu`) and formats it as Linux does, field for field, so the tools' parsers (busybox's `procps`, musl, Go) read it unchanged. Files are generated at `open`, so a reader sees one consistent snapshot even if it reads in small pieces.
- **What it has.** Per process: `stat`, `status`, `cmdline` (argv kept by `execve` from now on), `comm`, `environ`, `fd/` and `fdinfo/`, `exe`, `cwd`, `root`, `maps`, `task/<tid>/`. System-wide: `self`, `thread-self`, `uptime`, `loadavg`, `stat`, `meminfo`, `cpuinfo`, `version`, `filesystems`, `mounts` (and `self/mounts`), `sys/kernel/{hostname,ostype,osrelease,pid_max}`. Not a `/sys`, not writable tunables, not `/proc/<pid>/mem`.
- **Links that depend on who asks.** `self` reads as the caller's pid and `thread-self` as `<pid>/task/<tid>`; `fd/N`, `exe` and `cwd` read as the path the description was opened with (`pipe:[ino]`, `socket:[ino]`, `anon_inode:[eventfd]` for the others, as Linux). procfs's `Readlink` takes the caller through the walker (`lookup.go` passes the `Thread`), and opening `fd/N` opens the same file again, as Linux's "magic links" do (for a pipe or a socket: the same description), checked against the caller's permission to trace the target (same user, or root).
- **CPU time is counted by the nucleus.** `schedule()` adds the time since the last switch (TSC, converted with the calibration `time.c` already has) to the thread leaving the CPU, split into user and kernel by where it was; a new nucleus call reads a thread's two counters. Go sums them per process and keeps the children's totals at `wait4`; `times`, `getrusage`, `wait4`'s `rusage`, `/proc/stat`'s `cpu` lines and each `stat`'s `utime`/`stime` come from them, in clock ticks of 100 Hz (`sysconf(_SC_CLK_TCK)`).
- **virtio-blk is a `block.Device`.** `drivers/virtioblk` (1af4:1042): one request queue, each request a chain of three descriptors (the 16-byte header, the data pages, the status byte the device writes), several in flight, completions on the shared line; `VIRTIO_BLK_F_FLUSH` for `Flush`, `VIRTIO_BLK_F_RO` honoured, capacity from the device configuration. Disks are named `vda`, `vdb`, ... and mounted by label like the IDE ones, so the ext2 root and FAT homes just move. It passes `blocktest` against the fake device the transport's tests already have.
- **virtio-net is a `netdev.Device`.** `drivers/virtionet` (1af4:1041): a receive queue kept full of buffers, a transmit queue, the MAC from `VIRTIO_NET_F_MAC`, link state from `VIRTIO_NET_F_STATUS`; no offloads (no checksum, TSO or mergeable buffers: gVisor computes checksums), the 12-byte `virtio_net_hdr` zeroed on every frame. It registers `eth0` (or `eth1` beside an e1000), and gVisor's stack is unchanged.
- **DHCP in the kernel.** `kernel/netstack` gets a small DHCPv4 client (DISCOVER, OFFER, REQUEST, ACK; the lease's address, gateway and DNS server, renewed at T1) over gVisor's UDP; `/etc/net.conf` says `eth0 dhcp`, and the fixed addresses stay for images that keep them. Userland DHCP (`udhcpc`) would need `AF_PACKET`, which is not in this wave.
- **Named datagram Unix sockets** (E14.F08): `bind` a path on `SOCK_DGRAM`, `connect` to one and `sendto` with an address, the receiver's `recvfrom` reporting the sender's name; busybox `syslogd` and `logger` exercise it.
- **Tests read what tools print.** busybox's own applets are the checks (`ps` lists the shell, `top -b -n 1` shows `spin` near 100 %, `tty` names `/dev/pts/0`); `user/proctest` checks the formats field by field on the host's Linux and on Burrow, as `socktest` and `startup` do; the virtio drivers rerun the disk and network smokes on the other bus.

### [x] W23-S02 CPU time and top (E20.F02)
Nucleus: per-thread user and kernel TSC totals updated in `schedule()` and on ring-3 entry and exit, a call that reads them (NUCLEUS_ABI.md), a ktest that a spinning thread's user time grows and a blocked one's does not. Go: per-process sums, children's totals collected by `wait4`; `times`, `getrusage` (`RUSAGE_SELF`, `CHILDREN`, `THREAD`: `ru_utime`, `ru_stime`, `ru_maxrss`), `wait4`'s `rusage`; `/proc/stat` (`cpu` and `cpuN` lines with user, system and idle from the nucleus's idle threads, `ctxt`, `btime`, `processes`, `procs_running`), `<pid>/stat`'s `utime`/`stime`/`starttime`, `task/<tid>/`. busybox `TOP` and `TIME`. `proc-smoke`: `spin &` then `top -b -n 2` shows it above 90 % of a CPU; `time sleep 1` reports about a second of real time and nearly no user time; `proctest` checks `times` against a busy loop. `syslat` and `make smp-bench` budgets unchanged (the accounting is a few instructions per switch).
As built: `nucleus/cputime.c` charges a thread's time since its mark at every switch (`schedule_locked`), at every tick (`sched_on_tick`: a reader is never more than a millisecond behind) and when a user thread crosses rings (`trap_dispatch` and `nu_user_syscall` on the way in, `uthread_return_to_user` on the way out); the bucket is idle for a CPU's idle thread, user while a user thread is in ring 3, kernel otherwise (the nucleus and the Go kernel). Each counter is written only by the CPU running the thread, with IF=0, and only grows, so other CPUs read it with plain 64-bit loads and no sequence count was needed; readers see time up to the last charge, never a stint in progress. `nu_thread_times` (0x1029) and `nu_cpu_times` (0x102A, per CPU {user, kernel, idle, switches}); `kt_cputime` in the user suite (a kernel thread computing and sleeping, a thread spinning in ring 3, the CPUs keeping up with the clock). Go (`kernel/proc/cputime.go`): a thread's time is read just before it is killed (exit, `exit` of one thread, `execve`'s others) and kept as the process's; the total is fixed at exit, before it is a zombie; a parent adds a reaped child's (and the child's children's) in `waitChild`. Time Go spends serving a call is not the caller's: its nucleus thread waits, unscheduled, so `sys` is the ring crossings only. `times`, `getrusage` (now a thread handler), `wait4`'s and `waitid`'s `rusage` (`ru_maxrss`: the memory now, or at exit). procfs: `stat` at the root, the times in each `stat`, `task/<tid>/` with `stat`, `status`, `comm`, and `uptime`'s idle from the CPUs. busybox `TOP` (with the CPU percentages) and `TIME`. `proc-smoke` measures the spinning program's `utime` over 2 s (at least 150 ticks), finds it in `top -b -n 1` (26 % of four CPUs, 94 % of one: busybox's top divides by every CPU's time) and runs `time sleep 1`; `proctest` checks `times`, `getrusage`, `/proc/self/stat`, `wait4`'s rusage, the children's totals and `/proc/stat` growing against 300 ms and 200 ms busy loops, on the host's Linux and on Burrow (on four CPUs and on one).

Risks and pitfalls (PIT-NN entries go into BUGS_AND_MITIGATIONS.md when the wave starts):
- **Formats are a contract.** busybox, musl and Go parse `/proc` by position and by key; a missing field or a different unit breaks them quietly. `proctest` runs the same checks on the host's Linux, and the formats are copied from the kernel's documentation (`proc(5)`), not from memory.
- **Snapshots and locks.** procfs reads every process: it must take `s.mu` then each `p.mu` in the lock order, never hold a lock while copying out to the reader, and survive a process that exits between `readdir` and `open` (`-ENOENT`, not a crash).
- **Links that depend on the caller.** `self` and `fd/N` are not ordinary links: the walker must pass the caller into procfs, caching must not keep one caller's answer for another, and reopening `fd/N` must check the target's owner (a way into another user's files otherwise).
- **Time accounting on every switch.** The counters change on every CPU at every switch and every ring-3 entry; reading another thread's must not tear (64-bit stores, read twice), and the cost must stay out of `syslat`.
- **DMA chains and memory ordering, again.** virtio-blk's data descriptors point at pages the device writes, and many requests are in flight on four CPUs: the descriptor writes before the available index, the used index before the status byte, and no page reused until its request is done (W22's PIT on the used ring).
- **Two disk buses, one set of labels.** A label found on both an IDE and a virtio disk (a test that attaches the same image twice) must be refused loudly, not mounted twice.
- **DHCP and a fixed network.** QEMU's slirp always answers DHCP with 10.0.2.15; tests must not mistake the fixed configuration for a lease (the marker says `dhcp`), and a lease that never comes must time out and boot on.
