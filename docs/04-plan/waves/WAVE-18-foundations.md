# W18 Foundations for Bigger Programs  (M18)  — status: done

Goal: the machinery big programs take for granted: `fork` that shares memory until a write instead of copying it, `execve` that reads a program's pages as they are touched, memory processes share (`MAP_SHARED`, POSIX and SysV shared memory, `memfd_create`), and dynamic linking with musl's loader. Demo: Doom in an X window draws through MIT-SHM and keeps up with the fbdev Doom; a 100 MB process forks in milliseconds; a dynamically linked program and a `dlopen`ed library run on Burrow. Stories: E18 ([BACKLOG.md](../BACKLOG.md)).

Where we start (after W17): fork is an eager copy (`proc.Mem.Clone`, W10: every private page copied into a new frame); `execve` reads the whole file before it starts (BUG-0017: Qt's first frame was mostly loading); `mmap` of files is private only and writable `MAP_SHARED` is `-ENODEV` (W14-S05); there are no SysV calls, so TinyX's MIT-SHM extension (compiled in: `Xext/shm.c`) never works and every X image crosses the socket (W16-S05: Doom in X at a third of its fbdev rate); every program is static. What is ready: user memory is Go's policy over a nucleus that only maps frames (`Map`, `Unmap`, `PageAlloc`, W9), user page faults reach Go with the write bit (`FaultIn`, W12-S03), file-backed areas fill on first touch (W14-S05), and the host's musl has a dynamic loader to compare against.

Design (mechanism in the nucleus, policy in Go, as ever):
- **Frames get owners, not one owner.** A frame may be mapped by several address spaces; `proc` counts references per frame and frees one only when the last mapping goes. Fork maps every private writable page read-only in both processes and marks it copy-on-write; a write fault copies the page (or, for the last owner, just makes it writable again). Kernel writes into user memory (`CopyOut`: `read`, signal frames, futex words) break the share the same way. Shared mappings and device memory are never copy-on-write.
- **A shared object is frames with a name.** `/dev/shm` (POSIX `shm_open`), `memfd_create` and SysV segments are one kind of object: a list of frames, read and written through the file layer and mapped `MAP_SHARED` directly, so every process sees the same bytes. `MAP_SHARED|MAP_ANONYMOUS` makes an unnamed one, which fork shares.
- **Lazy `execve`.** ELF segments become file-backed private areas (the `ReserveFile` of W14-S05) instead of being read in whole; the bss is a zero area. A program pays for the pages it touches.
- **Dynamic linking is user space.** The kernel's part is `PT_INTERP`: load the interpreter as well, start there, and pass `AT_BASE`, `AT_PHDR`, `AT_PHNUM` and `AT_ENTRY`; musl's `ld-musl-x86_64.so.1` (which is its `libc.so`) does the rest with `mmap`, `mprotect` and `open`. The initrd gains `/lib`.

### [x] W18-S01 Copy-on-write fork (E18)
Reference-counted frames in `proc.Mem`, fork sharing private pages read-only, write faults and `CopyOut` that copy on demand, exit that frees only unshared frames. Host tests with `proctest.Fake` (two processes writing the same page after fork see their own bytes; a page shared three ways; exit order; fork of a fork; a futex word and a `read` buffer in a shared page). A `forkbench` program (fork and exit of a process with 64 MiB touched, and the memory the system lost) on Linux and on Burrow, before and after; `make test` unchanged, since every smoke test forks.
As built: `kernel/proc/cow.go`. Each family of processes shares a `frameRefs` table (fork passes it on) counting owners of shared frames; `Mem.Clone` marks every private page `cow` and maps it read-only in both, keeping the program's protection in `page.prot` while the mapping drops the write bit (`hwProt`); `breakLocked` copies a page others still own (under the table's lock, before the count drops, so no owner can be writing it) or makes the last owner's frame writable again; frames are freed when their last owner lets go (`releaseLocked`: `munmap`, `MADV_DONTNEED`, exit). Writes that break a share: a ring-3 write fault, `CopyOut` (every system call that fills a user buffer, signal frames, `clear_child_tid`), the ELF loader, and `MADV_DONTNEED`'s clearing of a page outside any area; `mprotect` and `mremap` keep a cow page read-only underneath. The nucleus needed nothing: a remap is `Unmap` and `Map`, and Go runs with the kernel's CR3, so a process's stale TLB entries go when its CR3 loads again. Host tests (`cow_test.go`) cover the write paths, a three-way share in any exit order, zeroing, and a real read-only page. The first boot found what the fake could not: the dispatcher only sent not-present faults to `FaultIn`, so a write to a present, read-only page (error code 7) was SIGSEGV; write faults now go there too (`TestCowWriteFaultThroughTheDispatcher`). `user/forkbench` (in `make ports-smoke`, on the host's Linux first): fork of a 64 MiB process took 324 ms with the eager copy and takes 86 ms now (Linux: 2.2 ms); a waiting child cost 58 MB and now costs nothing measurable. What is left of the 86 ms is three nucleus calls per page; S06 batches them.

### [x] W18-S02 Lazy execve (E18)
`LoadELF` maps segments as file-backed private areas and the bss as a zero area, reading nothing up front; the pages fill at first touch. Measured on `make qt-bench` (first frame) and `make x11-bench` (st start), against W15-S05's and W16-S05's numbers, with the budgets tightened where it pays.
As built: `execve` and `Spawn` open the program (`openProgram`: the file system's own `ReadAt`, which tarfs, memfs and FAT all have; the first 256 bytes for `#!`) instead of `fs.ReadFile`; `LoadELF` makes the whole pages of each segment's file bytes a file-backed private area, copies the partial pages at a segment's edges at once (past its file size the file holds other sections, which must read as zero), and maps the bss at once. Measured, and the measurements decided the policy: a lazy program read page by page made Qt faster but st 25% slower (1.85 to 2.32 s); fault-around (one read of the aligned 64 KiB window, Linux's `fault_around_bytes`) gave st nothing; 256 KiB made it worse, because fontconfig maps many fonts and reads a little of each; a lazy bss cost 0.17 s, since a fault is a round trip through the dispatcher. Kept: fault-around for program images only (`area.program`), one page per fault for `mmap`, an eager bss. Result: Qt's first frame 1.33-1.53 s (1.8 s before; the budget goes from 3.5 to 2.5 s), the X server's first frame 0.65-0.70 s (0.80), st as before (1.85 s). `qtbench`'s memory figure can read negative now (the kernel no longer reads 15 MB into its heap first, and its heap gives frames back while Qt starts); the budget script accepts that.

### [x] W18-S03 Shared memory: MAP_SHARED, /dev/shm and memfd (E18)
Shared objects in a `kernel/proc` (or `kernel/fs/shmfs`) package: `/dev/shm` files (`shm_open`, `shm_unlink` are open and unlink there), `memfd_create`, `ftruncate` growing and shrinking them, `read`/`write`/`mmap(MAP_SHARED)` all on the same frames; `MAP_SHARED|MAP_ANONYMOUS` shared across fork; `msync` accepted. Writable `MAP_SHARED` of files elsewhere stays `-ENODEV`. A `shmtest` program (two processes through each kind) on Linux and on Burrow.
As built: `kernel/proc/shm.go` and `shmcalls.go`. A `shmObj` owns its frames (allocated at first touch, zero until written) and counts its holders: open handles and mapped pages, while a `/dev/shm` name keeps it alive too; the last one frees the frames. A page mapped from one carries `page.shm`: never copy-on-write, never freed by the process, shared as it is by fork. `MAP_SHARED|MAP_ANONYMOUS` makes an unnamed object of the mapping's size; `MAP_SHARED` of a `/dev/shm` file or memfd maps the object's frames from the offset (`ReserveShared`); `MAP_PRIVATE` of one is an ordinary private file mapping. `/dev/shm/<name>` is handled in `openat` and `unlinkat`, as `/dev/ptmx` is, in a table per system (not a file system: `ls /dev/shm` shows nothing). `user/shmtest` (15 checks) passed on the host's Linux, then on Burrow except for three: `pread64` and `pwrite64` had never been implemented, since no program had asked; they are now (`prw.go`, through `io.ReaderAt`/`io.WriterAt`; `wfile` gained `WriteAt`). Host tests: a child's write through `read(2)` into shared anonymous memory shows in the parent; a memfd's frames go after its descriptor and both mappings.

### [x] W18-S04 SysV shared memory and MIT-SHM (E18)
`shmget`, `shmat`, `shmdt`, `shmctl` (`IPC_STAT`, `IPC_RMID`: gone at the last detach) over S03's objects. TinyX's MIT-SHM then works as built; Doom's X backend uses `XShmPutImage` when the server offers it (falling back to `XPutImage`), and `make x11-bench`'s Doom share rises (the budget with it). `x11-census` and `x11-smoke` keep passing; xhello learns to report whether MIT-SHM is there.
As built: `kernel/proc/sysv.go`. A segment is S03's shared object plus a key, its permissions and `shm_nattch`; it holds the object until `IPC_RMID` and the last detach. Attachments live in each `Mem` (address to segment), so `fork` inherits them in `Clone` and exit and `execve` detach them in `Close`, with no other code involved. `shmtest` gained seven SysV checks (two processes, `IPC_STAT`, `IPC_RMID` while attached, `shmdt`, gone after the last detach), on the host's Linux and on Burrow. TinyX needed nothing: its MIT-SHM was built all along and simply failed without `shmat`. Doom's X backend asks for it (`XShmQueryExtension`, a segment from `shmget`, `XShmAttach` under a temporary error handler, `IPC_RMID` at once), lets Doom draw straight into the segment when its rows are unpadded, and draws with `XShmPutImage` followed by `XSync`, so the server has read a frame before the next is drawn; without MIT-SHM it falls back to `XPutImage`. It says which on the console (`doom: drawing through MIT-SHM`, an x11-smoke marker). `make x11-bench`: Doom in X went from 37 to 88 fps with the copy into the segment and 95 fps without it, 0.76 of the fbdev Doom's 125 (budget 0.25 -> 0.6). The xhello report was not needed: Doom's line says it. Open for S06: st's start read 2.0-2.4 s over five runs since S03, against single runs of 1.90 s (S01) and 1.85 s (S02); nothing in st's libraries uses MIT-SHM, so S06 measures several runs of each build before calling it a change.

### [x] W18-S05 Dynamic linking (E18)
`PT_INTERP` in `execve` with the auxiliary vector musl's loader reads; `/lib/ld-musl-x86_64.so.1` (musl's `libc.so`, from the ports' toolchain) on the initrd; a dynamic `dynhello`, a shared library it links against, and a `dlopen`/`dlsym` test, checked on the host's Linux first and then on Burrow in `make ports-smoke`. TinyCC's `-run` (which needs a dynamic `tcc`) if it comes for free.
As built: `LoadELF` records `PT_INTERP` instead of refusing it; `prepare` then loads the interpreter (`LoadInterp`: an ET_DYN, at `InterpBase` = `0x7F0000000000`, below the stack and far from `mmap`'s region) and starts there, and `BuildStack` adds `AT_BASE`; `AT_PHDR`, `AT_PHNUM` and `AT_ENTRY` already described the program. musl's loader is the host's (`MUSL_LOADER`, the `libc.so` the user programs' `musl-gcc` links against), on the initrd as `/lib/ld-musl-x86_64.so.1`, with `user/dyn`'s `libgreet.so` and `libplug.so`. `dynhello` (a PIE linked against `libgreet.so`, opening `libplug.so` with `dlopen`) passed on the host's Linux (`LD_LIBRARY_PATH` at the build's libraries) and then on Burrow at the first boot, in `make ports-smoke`: the loader needed nothing the kernel did not already serve (`mmap` of files with `MAP_FIXED`, `mprotect`, `open`, `read`). TinyCC's `-run` did not come for free: the ports' `tcc` is static; a dynamic one is for later.

Risks and pitfalls (PIT-NN entries go into BUGS_AND_MITIGATIONS.md when the wave starts):
- **Copy-on-write is easy to get almost right.** Every path that writes user memory from the kernel must break the share (`CopyOut`, the signal frame, `futex` wake-ups that write, `clear_child_tid`, the ELF loader); a missed one corrupts another process silently. Host tests write through each path after a fork.
- **Stale translations.** Making a page read-only in a running process needs its TLB entry gone; the nucleus maps and unmaps with `invlpg` on the current space only, so remapping in a space that is not current must not leave an old writable entry behind when it runs again (one CPU: a CR3 load flushes, but check the global-page rules).
- **Frames freed twice or never.** Reference counts across fork, exit, `munmap`, `mremap`, `execve` and shared objects; a census of free frames before and after the smoke tests (the `mem` command) catches leaks.
- **Shared objects outlive processes.** SysV segments stay until `IPC_RMID` and the last detach; `/dev/shm` files until unlinked; a memfd until its last descriptor and mapping go.
- **Dynamic programs read more of the system.** `ld.so` looks for `/etc/ld-musl-x86_64.path` and the library path, and wants `mmap` with `MAP_FIXED` over its own reservations and `mprotect` on file mappings; the census of a dynamic program on Linux shows what else.
