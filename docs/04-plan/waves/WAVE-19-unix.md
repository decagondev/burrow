# W19 A Multi-User Unix  (M19)  — status: in progress

Goal: the part of Unix that is about people: users and groups, files with owners and permissions, symbolic and hard links, and a file system that keeps all of it (ext2). Demo: Burrow boots from an ext2 root disk to a `login:` prompt; user `burrow` logs in, cannot write `/etc/passwd` ("Permission denied"), makes a symbolic link in their home, `su`s to root with a password and adds a user; after a reboot the new user logs in and everything is still there; `e2fsck -fn` finds the disk clean. Stories: E19 ([BACKLOG.md](../BACKLOG.md)).

Where we start (after W18): every process is root: `getuid` and its family answer 0 (`zeroFn` in `kernel/proc/syscalls.go`), `SCM_CREDENTIALS` sends uid 0, and there are no `set*id` calls. Permissions are reported but never checked: `chmod`, `chown` and `lchown` succeed and change nothing (`metacalls.go`), and `umask` is kept with nothing to mask. Nothing is a link: `lstat` is `stat`, `readlink` is `-EINVAL` (`stat.go`), and paths are resolved by text (`cleanPath`: `path.Clean`, so `a/b/..` is `a` whatever `b` is). The file systems have no place for owners: the initrd is a tar packed `--owner=0` (tarfs ignores the headers' owners and links), FAT32 has neither owners nor links, and memfs (`/tmp`) keeps a mode only. `/etc/passwd` holds root alone. What is ready: a mount table over `io/fs` with writes through `vfs.Writable`, a block layer with ATA writes and its conformance tests (W13), a FAT writer checked against `fsck.fat` (the model for checking ext2 against `e2fsck`), lazy `execve` that reads programs through `ReadAt` (W18-S02), busybox with its user applets one config line away, and e2fsprogs 1.47 on the host (`mke2fs -d`, `e2fsck`, `debugfs`).

Design (policy in Go; the nucleus is not involved):
- **ext2, revision 1, no journal (ADR-0010 in S01).** The file system Linux had for a decade: owners, modes, links, sparse files, and a format e2fsprogs creates, inspects and repairs on the host. `kernel/fs/ext2` reads and writes it over a `block.Device`: the superblock, group descriptors, block and inode bitmaps, inodes with direct, indirect, double and triple indirect blocks, linear directories (an `htree` index is read as linear and dropped on a write, as Linux does), fast and slow symbolic links. It refuses a volume with an unknown incompatible feature and mounts one with an unknown read-only-compatible feature read-only. ext3's journal and ext4's extents are later; no journal means a crash can leave work for `e2fsck`, as FAT does now.
- **Credentials are per process.** A `Cred` (real, effective and saved user and group ids, supplementary groups) on each `Process`, copied by fork, changed by `execve` of a set-user-id or set-group-id file and by the `set*id` calls with Linux's rules. Linux keeps credentials per thread; musl changes all threads at once anyway (`__synccall`), so per process is what programs see. Root (effective uid 0) passes every permission check except `execve` of a file with no execute bit; there are no capabilities.
- **Owners live in the file systems; checks live in the kernel.** `fs.FileInfo.Sys()` gives a `vfs.Attr` (uid, gid, mode with set-uid, set-gid and sticky, link count, inode number). File systems with nowhere to keep owners give one for the whole mount (FAT: `uid`/`gid`/`umask`, as Linux's `vfat` options; devfs: root, with each device's mode). Creating calls take the caller's owner and the umasked mode, so a file never exists with the wrong owner. `kernel/proc` checks: search permission on every directory of a path, read and write on `open`, write and search on the directory for create, unlink and rename (with the sticky bit's rule), execute on `execve`, owner or root on `chmod`, root on `chown`, the real ids for `access`/`faccessat`, and the same uid for `kill`.
- **Paths are walked, not cleaned.** One walker in `kernel/vfs` resolves a path a component at a time: it follows symbolic links (40 at most, then `ELOOP`; the last component only when asked, for `O_NOFOLLOW`, `lstat`, `AT_SYMLINK_NOFOLLOW`), takes `..` from where a link led and not from the text, crosses mounts, and hands back each directory it passed through for the permission check. Every path call goes through it; the text cleaning goes. File systems offer links through Go's `fs.ReadLinkFS` (`ReadLink`, `Lstat`) and, to make them, `vfs.Linker` (`Symlink`, `Link`).
- **The root can be a disk.** The initrd stays the root of every image the tests boot. A disk labelled `BURROWROOT` is mounted at `/` instead when it is there, with `/tmp` and `/dev` mounted over it as usual; `kernel/cmd/mkext2` (like `mkfat`, built on S02's writer) makes it from the busybox tree with owners and modes from a manifest, so the image is reproducible without root on the build machine.

### [x] W19-S01 Reading ext2 (E19)
`kernel/fs/ext2`, read-only: superblock and feature checks, group descriptors, inodes, the four kinds of block pointer, linear directories, symbolic links (`fs.ReadLinkFS`), file data through `ReadAt`; `fs.FileInfo.Sys()` gives `vfs.Attr`. Host tests build volumes with `mke2fs -t ext2 -d` (1 KiB and 4 KiB blocks, a sparse file, a file past the double indirect blocks, a long directory, an htree directory, both kinds of link) and run `fstest.TestFS` over them, skipping without e2fsprogs; `make ext2-interop` runs them, as `make fat-interop` does. The kernel tells FAT from ext2 when it probes a data disk (the ext2 magic at byte 1080) and mounts an ext2 volume by its label read-only. ADR-0010 records the choice of ext2.
As built: `kernel/fs/ext2` (`layout.go` the format's offsets and the superblock's checks, `ext2.go` mount and the path walk, `inode.go`, `blocks.go`, `dir.go`, `file.go`): an `fs.FS`, `fs.StatFS` and `fs.ReadLinkFS` whose `FileInfo.Sys()` is the new `vfs.Attr` (uid, gid, links, inode number, atime, ctime). `Open` and `Stat` follow links inside the volume (relative to the link, absolute from the volume's root, 40 at most, then `ELOOP`), `Lstat` and `ReadLink` do not; reads coalesce blocks that lie in a row and read holes as zeros, with indirect blocks cached per open file. Tests (`ext2_test.go`, 9 with subtests) use only volumes e2fsprogs made: `mke2fs -d` of a tree with a hard link, a fast and a slow link, a set-uid file, a sticky directory, a 300 KiB file and a 70 MiB sparse file (its last block behind the triple indirect block with 1 KiB blocks), on 1 KiB and 4 KiB blocks and revision 0 (e2fsprogs 1.47 spells it `-E revision=0`), owners set with `debugfs sif`, a 400-entry directory turned into an htree by `e2fsck -fyD`; `fstest.TestFS` over each, plus loops, absolute links and refused volumes. A 300-block file costs fewer than 24 disk reads. `make ext2-interop` (in `make test`; CI installs e2fsprogs) runs them with skipping turned into failure. The kernel probes each data disk for the ext2 magic before FAT and mounts an ext2 volume read-only by its label, logging as `[ext2]`; `stat` reports a file system's `vfs.Attr` (inode, links, owner, times) and the set-uid, set-gid, sticky and link bits (`TestStatReportsTheFileSystemsAttr`). On Burrow: `make disk-smoke` attaches an ext2 volume mke2fs made on hdc, at `/mnt`, and reads a file, a symbolic link to it and a hard link to it; it worked at the first boot. ADR-0010.

### [ ] W19-S03 Users and groups (E19)
`Cred` on `Process`: `getuid`, `geteuid`, `getgid`, `getegid`, `getresuid`, `getresgid`, `getgroups`, `setuid`, `setgid`, `setreuid`, `setregid`, `setresuid`, `setresgid`, `setgroups`, `setfsuid`, `setfsgid`, with Linux's rules for who may change what. Fork copies the credentials; `execve` of a set-user-id or set-group-id file changes the effective and saved ids (and `AT_SECURE` in the auxiliary vector says so). `kill` and `SCM_CREDENTIALS`/`SO_PEERCRED` use the real ids. A `user/credtest` program checks the rules; it runs on the host's Linux as root first (CI's runner can `sudo`), then on Burrow in `make ports-smoke`.

### [ ] W19-S04 Owners and permissions (E19)
Creating calls (`vfs.Writable`'s `WriteFile`, `Mkdir`, `MakeSocket`, and pipes' and sockets' names) take an owner and a mode with the umask applied, and a set-group-id directory gives its group. `chmod`, `fchmod`, `fchmodat`, `chown`, `fchown`, `lchown` and `fchownat` change ext2, memfs and FAT's mount-wide answer as Linux would. tarfs reads owners and modes from the tar headers, and the initrd is packed with real modes (`/tmp`'s mount point and `/tmp` itself 1777, `/etc/shadow` 0600). The checks of the design go into `kernel/proc`'s path calls, `open` and `execve`; `access` and `faccessat` answer with the real ids. A `user/permtest` program (a user denied, the owner allowed, root allowed, the sticky bit, a set-group-id directory) on the host's Linux, then on Burrow.

### [ ] W19-S05 Symbolic and hard links (E19)
The walker of the design in `kernel/vfs`, and every path call in `kernel/proc` moved onto it; `cleanPath` goes. `symlink`, `symlinkat`, `readlink`, `readlinkat`, `link`, `linkat` (`EXDEV` across mounts), `lstat` and `fstatat` with `AT_SYMLINK_NOFOLLOW`, `open` with `O_NOFOLLOW`, `unlink` and `rename` of a link (not its target), `ELOOP`, `getcwd` after a `chdir` through a link. Links in ext2 (S01 reads them; S02's writer makes them), memfs and tarfs (the tar's symbolic and hard links); `vfs.Linker` for the ones that can make them. A `user/linktest` program on the host's Linux, then on Burrow; host tests for the walker on a fake tree with loops, links across mounts and `..` after a link.

### [ ] W19-S06 Logging in, an ext2 root, M19 (E19)
busybox with `LOGIN`, `GETTY`, `SU`, `PASSWD`, `ADDUSER`, `DELUSER`, `CRYPTPW`, `ID`, `CHOWN`, `CHGRP`, `LN`, `STAT`, shadow passwords and set-uid applets (`FEATURE_SUID`: `su` and `passwd` are set-user-id root). `kernel/cmd/mkext2` builds `burrow-root.img` (label `BURROWROOT`) from the busybox tree with `/etc/passwd`, `/etc/group` and `/etc/shadow` (root and `burrow`), owners and modes from a manifest; `go-unix.img`'s init starts `getty` on the console instead of the shell. `make run-unix` boots it; `make unix-smoke` (part of `make test`; skips without busybox) types the demo of the goal over two boots and runs `e2fsck -fn` on the disk after. Docs: a "Users and permissions" guide (`docs/06-guides/UNIX.md`), POSIX_COVERAGE.md's new calls, MEMORY_MAP.md unchanged.

Exit: **M19 demo — a multi-user Unix.** The demo of the goal in `make unix-smoke`; `make ext2-interop` green; `credtest`, `permtest` and `linktest` pass on the host's Linux and on Burrow; `make clean test` green; DEVLOG wave entry.

Not in this wave: ext3/ext4 (a journal, extents), quotas, ACLs and extended attributes, capabilities, `/proc`, per-thread credentials, named datagram Unix sockets (E14.F08, wanted by `syslogd`), ssh (E17, which this wave makes possible).

Risks and pitfalls (PIT-NN entries go into BUGS_AND_MITIGATIONS.md when the wave starts):
- **A file system writer corrupts quietly.** A wrong free count or a block in two files shows only later; every write test ends with `e2fsck -fn`, and the random operation sequences are seeded and logged so a failure replays.
- **Endianness and sizes in the on-disk format.** ext2 is little-endian with fields that grew across revisions (`s_inode_size` is 128 or 256, `i_size_high` holds a file's upper 32 bits); host tests use images e2fsprogs made, not ones this code made, so the reader and writer cannot agree on a mistake.
- **Root-only test results.** Every program so far ran as root, so a missing check never showed; after S04 the smoke tests still run as root, and only `permtest` and `unix-smoke` run as a user, so each check needs a test that would fail without it.
- **The walker changes every path.** `..` stops being textual, so a program that relied on `cleanPath` (the console's `run`, `#!` scripts, `execve`'s own lookup, the `/dev/shm` and `/dev/ptmx` special cases) may resolve differently; S05 runs the full `make test` before anything else.
- **Set-user-id programs are an attack surface.** `AT_SECURE` must be set so musl ignores `LD_LIBRARY_PATH` for them, and a set-uid bit must be dropped when a non-root user writes the file, as Linux does.
- **Lazy `execve` from a disk.** A program on the ext2 root reads its pages from the disk at first touch (W18-S02); if the program is changed or deleted while it runs, the pages it still has to read must be the old ones (keep the inode until the last mapping, as Linux does: `ETXTBSY` for writes to a running program).
