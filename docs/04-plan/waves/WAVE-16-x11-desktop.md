# W16 An X11 Desktop  (M16)  — status: in progress

Goal: a real multi-window desktop on Burrow: the TinyX `Xfbdev` X server on `/dev/fb0`, the dwm tiling window manager, the st terminal and the dmenu launcher, started by `startx` from the shell. Demo: `make run-desktop` boots to `burrow>`; `startx` brings up dwm; Mod+Shift+Enter opens st windows that tile; `ls /home` runs in one, `vi` in another; Mod+p opens dmenu and starts Doom in a window (doomgeneric's X11 backend); Mod+Shift+q leaves dwm and the console comes back. Stories: E16 ([BACKLOG.md](../BACKLOG.md)).

Where we start (after W15): everything an X server on the Linux console asks for is already there: `/dev/fb0` with `FBIOGET_*` and `mmap` (W11), the keyboard as `K_MEDIUMRAW` key codes through the terminal and the mouse as `/dev/input/mice` speaking the IntelliMouse protocol (W14-S02, S08), `KDSETMODE`/`VT_*` with the console given back when the server dies (W14-S08), Unix sockets with names and descriptor passing for `/tmp/.X11-unix/X0` (W14-S06, S07), `select`/`poll`, file `mmap`, 512 MiB, both IDE channels and fast disk reads (W15). Static musl ports from pinned downloads and a census on Linux first are routine (W12, W15).

Design (continues W12-W15: pinned sources, static musl builds on the host, Linux first, then Burrow):
- **TinyX, not Xorg.** `Xfbdev` from TinyX (`github.com/tinycorelinux/tinyx`, the maintained X.Org 1.2.0 kdrive: no XKB, no XInput, no GL, no TCP by default) is a few MB and reads exactly the devices Burrow offers. The cost: no XKB means Qt 6's xcb platform and GTK3 stay out (E16, the 1.20-branch kdrive, later); dwm, st, dmenu, xterm and plain Xlib programs work.
- **The X libraries, static.** `scripts/x11.sh` downloads (pinned, a go-ahead first) and builds for musl: xorgproto, xtrans, libXau, libXdmcp, xcb-proto, libxcb, libX11, libXext, libXrender, libXft, libXinerama (dwm's optional), fontconfig with expat, FreeType, zlib, libXfont 1.5 with libfontenc (the server's core fonts), and the core font set (misc-fixed and cursor, PCF). Then TinyX, dwm 6.x, st 0.9.x and dmenu 5.x, each with a `config.h` in `user/x11/`. Everything lands in `build/x11-root` and on an X data disk (`x11-data.img`, label `X11DATA`, mounted at `/opt/x11`) like Qt's.
- **Fonts twice.** The server needs core fonts (`fixed`, `cursor`) in PCF with a `fonts.dir`; st and dmenu draw with Xft through fontconfig, which reads `/opt/x11/etc/fonts/fonts.conf` pointing at DejaVu (already pinned in W15). A fontconfig cache is built on the host so the first start does not scan.
- **Starting X.** No display manager: `user/x11/startx` (a busybox `sh` script, as `xinit` would be) starts `Xfbdev :0 -mouse mouse,/dev/input/mice -keybd keyboard` in the background, waits for its socket, runs `~/.xinitrc` (or `dwm`), and kills the server when that exits. The console's `run /bin/busybox sh -c startx` launches it; `make run-desktop` boots `go-dev.img` with the home, Qt and X disks.
- **No MIT-SHM yet.** SysV shared memory does not exist; the server is built without MIT-SHM and clients fall back to sending images over the socket. Writable shared memory is W18's (E18).

### [x] W16-S01 The X stack on Linux first (E16)
`scripts/x11.sh` and `make x11`: every library and program above, pinned and static, into `build/x11-root`. On the host (`xvfb`, `xdotool` and `xwd` from apt, a go-ahead), the static musl clients (`st`, `dmenu`, `dwm` and a small `user/x11/xhello.c`: an Xlib window that draws rectangles and text with core fonts and Xft, prints the events it gets and quits on a key) run against Xvfb; a census (`make x11-census`, `strace -f` of the clients and of `Xvfb`'s socket traffic) lists their system calls in `tests/regression/census-x11.txt`, checked by a test like `TestCensusQt`. `Xfbdev` itself cannot run on WSL (no fbdev); its census comes from Burrow's unimplemented-syscall log in S02.
As built: `scripts/x11.sh` (`make x11`; the second half, fonts and programs, is `scripts/x11-apps.sh`) fetches 26 pinned sources (15 MB; no project but zlib publishes a sha256 beside its file, so the pins are the files as first downloaded) and builds 18 libraries with autotools into a static musl sysroot in `~/.cache/burrow-x11`: zlib, expat, FreeType, xorgproto, xtrans, libXau, libXdmcp, pthread-stubs, xcb-proto, libxcb, libX11, libXext, libXrender, libXinerama, fontconfig (configured for `/opt/x11/etc`, installed through a staging tree), libXft, libfontenc and libXfont 1.5; all built at the first attempt. TinyX needed `ACLOCAL_PATH` for xtrans's m4 macros and one patch (`user/x11/patches/tinyx-xtest-header.patch`: `XTest.h` moved to libXtst long ago, and the file needs nothing from it). dwm, st and dmenu build from copies with `user/x11/*-config.h` (upstream's defaults, fonts as pixel-sized "monospace" through fontconfig). The core fonts are misc-misc and cursor, converted with the host's `bdftopcf` and indexed with `mkfontdir`; Xft gets DejaVu (W15's pin). The whole tree, eight programs and the fonts, is 17 MB. `tests/regression/x11-linux.sh` runs the static binaries against the host's Xvfb, driven by xdotool: `xhello` (`user/x11/xhello.c`) draws with the core font and Xft and quits on a key, st runs busybox `sh` and its output reaches a file (st's own exit status when its shell ends is a race in st, so it is judged by its work), dmenu returns the line chosen with Down and Return, dwm manages a window and quits on Alt+Shift+q. The census (`make x11-census`, `tests/regression/census-x11.txt`, checked by `TestCensusX11` with `TestCensusQt`'s code) is 48 calls plus `clock_gettime` (vDSO); three are missing on Burrow and named for S02: `fadvise64` and `fstatfs` (fontconfig) and `mremap` (musl's `realloc`). Not in the census, because a census counts calls and not ioctl requests (BUG-0016): st's pseudo-terminal requests (`TIOCGPTN`, `TIOCSPTLCK`, `TIOCSCTTY`, `TIOCSWINSZ`), which are S03's.

### [ ] W16-S02 Xfbdev on Burrow (E16)
The server on `go-dev.img` with the X disk: it opens `/dev/fb0`, maps it, takes the console (`KDSETMODE`, `KDSKBMODE K_MEDIUMRAW`), draws the root weave and the cursor, listens on `/tmp/.X11-unix/X0`, and gives everything back on SIGTERM and on a crash. What Burrow is likely to need: the console's keymap through `KDGKBENT`/`KDGKBSENT` (TinyX builds its keymap from the kernel's; Burrow answers with a US layout table), `ioctl(KDGKBMODE)` on `/dev/tty0`, `setitimer`/`SIGALRM` (the server's smart scheduler; or `-dumbSched`), `uname`, `/tmp/.X11-unix` with the sticky bit accepted. A screen check samples the weave and the cursor; the mouse moves it (W14's `mouse` steps).

### [ ] W16-S03 Clients: xhello and st (E16)
`xhello` connects over the Unix socket, opens a window, draws, gets key and button events; then `st` with Xft text from fontconfig, running busybox `sh` on a pseudo-terminal. That last part is new: st needs `/dev/ptmx` and `/dev/pts/N` (`posix_openpt`, `grantpt`, `unlockpt`, `ptsname`, `TIOCSWINSZ`), which Burrow does not have; a pseudo-terminal pair over `kernel/tty`'s line discipline is the slice's kernel work, with host tests and a `ptytest` program checked against Linux.

### [ ] W16-S04 dwm and dmenu (E16)
dwm as the window manager: tiling, tags, focus follows the keyboard and mouse, Mod+Shift+Enter starts st, Mod+p starts dmenu (which lists `/bin` and `/opt/*/bin` through `dmenu_path`, a busybox script), Mod+Shift+q quits. The smoke test opens two terminals, types into each, moves between them, switches tags, starts a program from dmenu and quits; serial markers come from the programs (st runs `sh -c` commands that echo to `/dev/console`) and screen checks sample the tiled layout and the bar.

### [ ] W16-S05 Doom in a window, and fast enough (E16)
doomgeneric's Xlib backend (`doomgeneric_xlib.c`) built against the static X libraries: Doom runs in a dwm window from dmenu. Budgets in `make x11-bench` (not in `make test`): server start to first frame, st start, an `ls` of 100 lines scrolled in st, Doom's timedemo frame rate in X against the fbdev one. Likely hot spots: image transfer over the socket without MIT-SHM, `select` wake-ups, and fork without copy-on-write when st starts a shell.

### [ ] W16-S06 startx, make run-desktop, and the desktop guide (E16)
`startx` and a default `.xinitrc` in `workbench/`, `make run-desktop`, `make desktop-smoke` (in `make test`, skipping without `make x11`): boot, `startx`, two terminals, `vi` in one, Doom from dmenu, quit, the console back, and a second boot to show the home disk untouched. `docs/06-guides/DESKTOP.md`: starting X, dwm's keys, st and dmenu, adding programs, and what TinyX leaves out.

Exit: **M16 demo — a desktop.** `make desktop-smoke` in `make test`; `make clean test` green; PORTING.md gains an X11 section (the library list, the configure lines, fonts, what is switched off); POSIX_COVERAGE.md has the pty calls and the new ioctls; DEVLOG wave entry.

Risks and pitfalls (PIT-NN entries go into BUGS_AND_MITIGATIONS.md when the wave starts):
- **Autotools cross builds.** Fourteen X.Org packages, each with `configure`, each liable to probe the host; a `--host=x86_64-linux-musl` toolchain prefix, `PKG_CONFIG_LIBDIR` pointing only at our own `.pc` files, and `--disable-shared` everywhere. xcb-proto needs the host's Python.
- **Pseudo-terminals are new kernel work.** st cannot run without them; S03 carries a full slice of tty work (master and slave ends, the line discipline on the slave, window size, `SIGWINCH`, the controlling terminal of a new session).
- **TinyX's input is 2006 Linux.** It reads the console keymap with `KDGKBENT` and drives the mouse through its own protocol detection on `/dev/input/mice`; both must answer as Linux did then.
- **No XKB.** Some clients assume it (Qt 6, GTK3, newer xterm builds with `--enable-xkb`); build what we ship without it and keep a list.
- **Fork copies eagerly.** Every st forks a shell, every dmenu forks the chosen program; with a few hundred MB of X clients this is where copy-on-write fork (W18) starts to matter.
- **Licences.** TinyX's changes are GPLv3 on an MIT base; dwm, st and dmenu are MIT/X; the X libraries are MIT-style. Burrow ships the pinned sources and the build script.
