# W20 Many CPUs, Hardened  (M20)  — status: in progress

Goal: Burrow on every CPU the machine has, with the CPU's own protections switched on. Demo: QEMU boots with four CPUs (`-smp 4`, multi-threaded TCG); `[nucleus] smp: 4 CPUs online`; busybox's `nproc` says 4; a CPU-bound program with four threads finishes in well under half the time it takes on one CPU; the Go kernel runs with `GOMAXPROCS=4`; SMEP and SMAP are on, so the kernel can neither run nor touch user memory by mistake; `poweroff` turns the machine off through ACPI; `make test` is green on four CPUs. Stories: E12 ([BACKLOG.md](../BACKLOG.md)).

Where we start (after W19): one CPU. The nucleus has one `struct percpu` (`g_percpu`: the current thread, its kernel stack, a syscall scratch slot), read by `trap.asm` and `syscall.asm` at fixed offsets; the scheduler keeps all its state with interrupts off; spinlocks are already atomic and IRQ-saving ("correct for SMP later", `spinlock.h`); the LAPIC sends self-IPIs only; the time base is the TSC calibrated against the PIT, with a 1 ms tick. `sched_getaffinity` answers one CPU, so the Go runtime runs with one P, which is behind BUG-0014's `Gosched` workaround and makes every blocking nucleus call hold the only P. QEMU runs `-cpu qemu64` (no SMEP, SMAP or AVX) and no `-smp`. NX is in use (W^X nucleus, Go segments); CR0.WP is on; SMEP and SMAP are not. The FPU state is FXSAVE (x87 and SSE only). `poweroff` writes QEMU's debug-exit port: nothing would turn real hardware off, and there is no ACPI. What helps: the Go kernel never dereferences user addresses (copy-in and copy-out go through the physmap, W9), page tables are built by mechanism the nucleus already has, and BUG-0023 (a rare hang of a parent waiting for its child) is the kind of race more CPUs make worse, so it is first.

Design (mechanism in the nucleus, policy in Go, as ever):
- **Protections before parallelism.** SMEP (no kernel execution of user pages) and SMAP (no kernel access to user pages outside `stac`/`clac`) are switched on while there is still one CPU, so a fault they raise is a bug found, not a race; the nucleus's few user accesses (if any) are bracketed. XSAVE replaces FXSAVE (the area sized by CPUID), and only then may QEMU offer AVX (`-cpu max`), which the Go runtime and musl will use.
- **ACPI for what the machine is.** A pure C module (host-tested on tables captured from QEMU) finds the RSDP, walks the RSDT/XSDT, and reads the MADT (the CPUs' APIC ids, the I/O APIC) and the FADT; `poweroff` writes the `\_S5` sleep type to PM1a_CNT (found by the classic scan of the DSDT for `_S5_`), falling back to the debug-exit port under test.
- **Per-CPU state through GS.** Each CPU has its own `struct percpu`, GDT, TSS, IST stacks and LAPIC timer, reached through `GS_BASE` (the nucleus's; Go's TLS stays FS, PIT-04). `trap.asm` and `syscall.asm` read `gs:` offsets instead of a global.
- **Application processors.** The BSP starts each AP with INIT-SIPI-SIPI into a real-mode trampoline below 1 MiB that climbs to long mode on the nucleus's page tables and enters the scheduler's idle loop on its own stacks.
- **One run queue first.** All CPUs take threads from one locked run queue (per-CPU queues and balancing are a later refinement); a wake-up of a thread that should run sends a reschedule IPI to an idle CPU; a thread's FPU state and kernel stack go with it. Futexes and the syscall FIFO are already spinlocked; their waits must be correct when the waker runs on another CPU.
- **TLB shootdown.** An address space records the CPUs it is live on; unmapping or write-protecting a page (copy-on-write, `munmap`, `mprotect`, `nu_as_protect`) sends an IPI to the others and waits for their acknowledgement before the frame is reused. Kernel mappings change rarely and flush everywhere.
- **Go on every CPU.** `sched_getaffinity` (and `/sys`-free `sysconf(_SC_NPROCESSORS_ONLN)`, which musl answers from `sched_getaffinity`) reports the CPUs online; the Go kernel runs with that many Ps; user threads run on any CPU. BUG-0014's `Gosched` stays (it is correct) but no longer carries the system.

### [x] W20-S01 BUG-0023, and a hang watchdog (E12)
Before anything changes: a way to see a hang, and the one we have. A key the smoke harness sends when a boot times out (`tests/smoke/smoke.sh`, through QEMU's monitor) makes the Go kernel print every process and thread with its state and what it waits on (`[proc] dump ...`), so every future timeout leaves evidence. A stress program (`user/waitstress`: many children, some with threads, exiting while their parents wait, with signals in flight) and a loop target reproduce BUG-0023 more often than one run in twenty; then find it, fix it, and keep the stress program in `make test`.
As built: `proc.System.Dump` (`dump.go`) prints every process (pid, parent, group, state, path, pending signals) and thread (the system call in flight and for how long, recorded with atomics in `handle`; mask, pending), then the stacks of the goroutines in `kernel/proc`, taking no lock a stuck thread might hold. Alt+SysRq on the console's keyboard runs it (`vtkeys.go`: scancode 0x54, swallowed; plain SysRq is PrintScreen's sequence in QEMU); `tests/smoke/sendkeys.py` presses it whenever a keys step fails, and `smoke.sh` gives sendkeys a deadline six seconds before QEMU's, so every timed-out smoke now ends with a dump. `user/waitstress` (six ways for a child to end, with SIGCHLD and `waitpid(-1)`) passed on the host's Linux and runs 100 rounds in `make ports-smoke` (now 120 s). BUG-0023 did not reproduce: about 5,000 waitstress rounds and 255 `gohello` runs over 17 boots, nine of them three at a time; it stays open, with the trap set. The first dump found BUG-0026 instead: a thread that ended while blocked (in `pause`, a read, a futex wait) left its handler goroutine waiting for ever, 30 of them after 50 rounds; `exit` and `execve` now wake them and `finish` answers no ended thread; none are left after 100 rounds.

### [x] W20-S02 SMEP, SMAP and NX everywhere (E12)
CPUID checks; CR4.SMEP and CR4.SMAP set at boot when the CPU has them (QEMU: `-cpu qemu64,+smep,+smap` for every image); every place the nucleus reads or writes a user address (if any: `uregs.c`, the ring-3 ktests, the fault paths) bracketed with `stac`/`clac` in `cpu.h`. An audit that user pages are NX unless mapped executable, and that the kernel's data, stacks and the physmap are NX. ktests: a kernel read of a user page faults with SMAP (a `.fixup` probe), a kernel jump to a user page faults with SMEP; regression cases for both (`with_ktest`).
As built: `nucleus/protect.c` reads CPUID leaf 7 and sets CR4.SMEP and CR4.SMAP after `vmm_init`, and checks EFER.NXE: `[nucleus] protections: smep on, smap on, nx on ok`, now a `boot_to_nucleus` marker. `cpu.h` has `stac`/`clac`, and none is needed: the nucleus and the Go kernel reach user memory only through the physmap (`kernel/proc`'s copy-in and copy-out, `uspace_translate`), which the full `make test` with SMAP on confirms: every smoke, Doom, X, Qt, the network and the logins pass. QEMU's CPU is `QEMU_CPU ?= qemu64,+smep,+smap` (Makefile, `smoke.sh`, the regression script). ktests in the mm suite (`ktest_protect.c`, with a new `probe_exec` that resumes a fetch fault at its target through trap.c): a real user page (a uspace address space, so every level has the U bit, its CR3 loaded with interrupts off) faults on a ring-0 read (present, supervisor: SMAP), reads with `stac`, and faults on execution with or without `stac` (an instruction fetch: SMEP); the nucleus's own data faults on execution (NX). On `qemu64` without the flags the ktest fails at its first check, as it should. The NX audit found nothing to fix: the physmap, nucleus data, kernel stacks, MMIO, the Go kernel's memory and user pages are all NX unless mapped executable. The regression cases planned for SMEP and SMAP were not needed: the probes recover, so ktests check both directly.

### [x] W20-S03 XSAVE and a CPU with AVX (E12)
The FPU area per thread sized by CPUID leaf 0xD, saved with XSAVE (XSAVEOPT where present) and restored with XRSTOR, XCR0 set to what the CPU offers (x87, SSE, AVX); `nu_uthread_regs` keeps returning the legacy 512-byte FXSAVE part. Then QEMU's CPU model becomes one with AVX (`-cpu max` or a named model, with SMEP and SMAP); a ktest dirties YMM upper halves in two threads and checks each keeps its own; Go's runtime (which uses AVX2 for `memmove` when CPUID says so) and Doom run unchanged; the census does not change.
As built: `nucleus/fpu.c` enables XSAVE when CPUID leaf 1 has it and leaf 0xD describes x87 and SSE: CR4.OSXSAVE, XCR0 = x87 | SSE | AVX (if offered), the area's size from leaf 0xD (832 bytes) checked against a thread's 1024-byte, 64-byte-aligned area (`FPU_AREA_BYTES`); a thread switch saves and restores with `xsave64`/`xrstor64`, else FXSAVE as before (the fallback the sched suite passes on `qemu64`). Plain XSAVE, not XSAVEOPT as planned: XSAVEOPT may leave the legacy region unwritten for components it thinks unchanged, and Go reads that region for signal frames. `fpu_set_legacy` writes FXSAVE-format registers into an area and marks x87 and SSE present in its header, so XRSTOR loads them (a fork child's state, `uregs` writes); before, a 512-byte copy into the bigger area would have read past its source. `[nucleus] sse ok (xsave per thread: x87 sse avx, 832 bytes, mxcsr=1f80)`. QEMU's CPU is `Broadwell-noTSX-IBRS` (SMEP, SMAP, XSAVE, AVX, AVX2): `qemu64` with `+xsave` hangs QEMU 10.0's TCG on the CR4.OSXSAVE write (no fault, RIP stuck on the `mov`), while `max`, Haswell and Broadwell run; Broadwell also brings RDRAND, which `kernel/random` now seeds from. ktest `avx_state_per_thread` (sched suite; `ktest_sse.asm` reaches ymm0's upper half): two threads keep different upper halves across a hundred switches, and main its own; it fails on a CPU without AVX. Not done: signal frames still carry only the FXSAVE part, so a signal handler that uses AVX may change the interrupted code's upper halves (Go's handlers and musl do not use AVX).

### [x] W20-S04 ACPI: the machine's tables, and poweroff (E12)
`nucleus/acpi.c` (pure, host-tested in `tests/unit/c/test_acpi.c` on tables dumped from QEMU's pc machine): RSDP in the EBDA and the BIOS area, RSDT and XSDT with checksums, the MADT (local APIC ids, enabled flags, I/O APIC address), the FADT (PM1a control block), and the `\_S5` sleep type from the DSDT. boot_info gains the CPU list (a version bump, mirrored in `boot_abi.inc` and MEMORY_MAP.md as the contracts require) or the nucleus reads the tables itself; `[nucleus] acpi: 4 CPUs, I/O APIC at ...` marker with `-smp 4`. `poweroff` turns QEMU off through ACPI when it is not under test (the smoke tests keep the debug-exit port, which carries the pass/fail code).
As built: `nucleus/acpi.c` (pure, in `UNIT_SRC`; physical memory through an `acpi_mem` callback): the RSDP in the EBDA's first KiB or 0xE0000-0xFFFFF with its checksums (the 36-byte one for ACPI 2.0+), the XSDT when there is one, else the RSDT, tables with a bad checksum skipped, the MADT (enabled processors' APIC ids, the first I/O APIC, an APIC address override), the FADT (SCI, SMI command, ACPI enable value, PM1a/PM1b control, the DSDT or X_DSDT) and `\_S5` by the usual scan of the DSDT's AML (NameOp, optionally with a root prefix, `_S5_`, PackageOp, PkgLength, NumElements, two elements with or without BytePrefix), each byte bounded by the table's length. `tests/unit/c/test_acpi.c` builds QEMU-like and ACPI 2.0 tables byte by byte (an RSDT and Package of four Zeros; an EBDA RSDP, an XSDT preferred over an RSDT, X_DSDT, an override, BytePrefix values) and broken ones; its first run found the scan's bound too strict for a package near a table's end. The boot_info contract did not change: the nucleus reads the tables itself (`acpi_boot.c`, through the physmap, each end probed so an address past it is "not there" rather than a fault) and prints `[nucleus] acpi ok (1 CPU, apic ids 0; I/O APIC 0 at fec00000; S5 found on port 604)`, now a `boot_to_nucleus` marker; `make acpi-smoke` boots the nucleus with `-smp 4` and wants `4 CPUs, apic ids 0 1 2 3`. `nu_debug_exit(0x10)` still writes the debug-exit port first (the tests' pass code), and if the machine is still running turns it off through S5, after the SMI command if ACPI mode is off; `make poweroff-smoke` (`tests/smoke/poweroff.py`) boots go.img with no debug-exit device, types `poweroff` on the serial line, and passes only when QEMU exits by itself with status 0.

### [x] W20-S05 Application processors (E12)
Per-CPU `struct percpu` through `GS_BASE` (the asm offsets become `gs:` reads; as built, `swapgs` on every ring-3 entry and exit, since ring 3 can reload GS: ADR-0011); per-CPU GDT, TSS and IST stacks; per-CPU LAPIC enable and timer. The trampoline (`nucleus/ap.asm`, copied to a page below 1 MiB that the loader reserves in the memory map) takes each AP from real mode to long mode on the kernel's page tables; the BSP sends INIT-SIPI-SIPI with the SDM's delays and waits for each AP to check in. APs run the idle loop only. ADR-0011 records the per-CPU and run-queue design. Markers: `[nucleus] smp: cpu 1 online` for each, `[nucleus] smp: 4 CPUs online`; a ktest counts a spinlocked counter from every CPU.
As built (ADR-0011): `g_cpus[SMP_MAX_CPUS=16]` with `self` at +32 (`this_cpu()`, one `gs:` load; `thread_current` reads `gs:16`), bound by `gdt_init_cpu` after `gdt_load`. `trap_common` swaps when the saved CS is ring 3 and `trap_resume` when it returns there; #DF/NMI look at `GS_BASE` itself. SYSCALL has two entries, `syscall_entry_user` (starts with `swapgs`) and `syscall_entry_kernel`; `schedule()` points LSTAR at the one for the next thread's kind (`syscall_set_entry`). Each CPU has its own GDT and TSS; APs' idle and IST stacks are mapped at `AP_STACK_REGION`. `nucleus/ap.asm` is copied to physical 0x8000 and goes from real mode straight to long mode on a temporary PML4 (the kernel's entries plus the first 2 MiB identity-mapped, frames below 4 GiB, freed afterwards), with the BSP's CR0, CR4 (less PCIDE) and EFER (less LMA); `ap_main` switches to the kernel CR3 and sets up GDT/TSS/GS, the IDT, its LAPIC (LINT0 masked), XCR0/MXCSR and the SYSCALL MSRs, then idles (`sti; hlt`) until `smp_run_everywhere` puts a function in its mailbox and sends the wake IPI (vector 0xF0). The AP timer waits for S06. Markers: `[nucleus] smp: cpu N online (apic id N)` and `[nucleus] smp: 4 CPUs online` in `make acpi-smoke`, `smp: 1 CPU online` in `boot_to_nucleus`. ktests: suite `smp` (on `-smp 4`: `smp_cpus_online`, `smp_percpu`, `smp_spin_counter` with 200000 locked additions per CPU) and `uthread_gs_reload` in suite `user` (ring 3 loads GS, then a syscall and timer interrupts; the kernel's base survives). PIT-60 lists the globals S06 must lock. The trampoline started all three APs on the first boot; the regression case for a broken trampoline waits for S06, when an AP that does not start can matter.

### [x] W20-S06 Scheduling on every CPU (E12)
One run queue under a spinlock, taken by every CPU's idle loop and timer tick; reschedule IPIs (a vector of the nucleus's) when a thread becomes runnable and a CPU is idle; `thread_block_unlock` (PIT-23) and futex wake-ups correct when waker and sleeper run on different CPUs; the syscall FIFO's waiter (`nu_syscall_wait`) woken across CPUs; a thread's FXSAVE/XSAVE area, kernel stack and FS base move with it (PIT-22's list, per CPU). ktests: many threads ping-ponging through futexes across CPUs, a migration check, the existing sched and sync suites with `-smp 4`; `make ktest` runs every suite on 1 and 4 CPUs.
As built (ADR-0011): `sched.c` keeps switching, blocking, waking, the tick and the idle loop; creation, joining and lookup moved to `thread.c` (`sched_priv.h` between them). `g_sched_lock` is held across `switch_to` and dropped by the thread switched to: `thread_bootstrap` for a new kernel thread, `thread_start_frame` (switch.asm) before `trap_resume` for one made from a frame. `thread_block_unlock` marks the thread blocked under `g_sched_lock` before the object's lock drops; wakers take the object's lock, then `g_sched_lock` (futex, `irq.c`, the uthread FIFO and `nu_syscall_wait` unchanged). Every CPU has an idle thread (an AP's boot context is adopted by `sched_init_cpu`) that runs its mailbox, then any runnable thread, else `sti; hlt`, and a LAPIC timer at 1 kHz from the BSP's calibration (`time_init_cpu`); CPU 0's tick wakes sleepers and counts `time_ticks`. A thread that becomes runnable sends the wake IPI (0xF0) to one idle CPU allowed to run it (`sched_kick`). `pin_cpu`: kernel threads run anywhere; `main` and every thread from a trap frame (Go's Ms, user threads) stay on CPU 0 until S07, because a page-table change is still flushed on the changing CPU only. For the same reason a kernel stack is freed at join only when the joiner is the only CPU that ever touched it (`stack_cpus`), else it stays mapped for its slot's next thread. `frames.c` and `vmm.c` have spinlocks (order: address space, `vm`, `frames`); kprintf's guard is a cross-CPU spinlock with a bounded spin (`spinlock.c`), so a panic still prints; `lapic_send_ipi` keeps IF off between its two ICR writes. ktests in suite `smp`: `smp_threads_everywhere` (a busy thread per CPU, every CPU runs one), `smp_futex_ping_pong` (four pairs, 20,000 round trips each, about 350 ms on four CPUs), `smp_migration` (four threads that sleep and yield keep their FS base and xmm0, and at least one moves); `make ktest` runs every suite with `-smp 1` and `-smp 4` (smp only on four), and the four-CPU sched and smp suites passed ten runs in a row. REG-0008 (`smp_broken_trampoline`, `-smp 2`): smp.c writes `jmp $` over the trampoline's first bytes, the AP is reported (`smp: cpu with apic id 1 did not start`) and the test fails; a `hlt` there was not enough, since QEMU resumes a halted AP at the second STARTUP IPI and it ran on into the real trampoline. Go images are unchanged in behaviour: their threads all stay on CPU 0.

### [x] W20-S07 TLB shootdown, and user threads everywhere (E12)
Each address space keeps the set of CPUs it is loaded on; unmapping, write-protecting or remapping a page sends a shootdown IPI to the other CPUs in the set and waits for them before the frame can be reused (`nu_as_protect` and `nu_as_map_batch` shoot down once per batch); kernel mapping changes flush on every CPU. ktests: a thread on one CPU writes a page another CPU then write-protects (copy-on-write) and must fault; a freed frame is never written through a stale entry. User threads (musl pthreads, Go user programs) run on any CPU; `threads`, `gohello`, `forkbench` and `shmtest` pass with `-smp 4`.
As built (ADR-0011): `nucleus/tlb.c`. An address space's CPU set is not stored in it: each CPU publishes the root it runs on (`percpu.cr3`, set by `schedule_locked` right after the mov to CR3, by `vmm_init` and `ap_main` at boot), and a shootdown reads them after a full fence that follows the entry writes; an upper-half change goes to every CPU. `vmm.c`'s `flush` is `tlb_shootdown`: `vm_unmap`, `vm_protect` and discards are shot down before they return, and the frames an unmap or discard frees wait in a batch (`free_batch`, 64 entries) until one shootdown covers them; `vm_discard_pages` (madvise of a range) discards a range with one shootdown per batch; `vm_map` replaces nothing (`PT_ALREADY_MAPPED`) and needs none. Batches of `nu_as_protect` are one `vm_protect`, so one shootdown; `nu_as_map_batch` maps only. Deadlock: a sender waits with IF off, so every spinlock loop, kprintf's guard and `smp_run_everywhere`'s wait call `tlb_poll`, which answers this CPU's pending request; one shootdown runs at a time (`g_shoot_lock`, itself polled). Then `thread_create_user` stops pinning (Go's Ms and user threads run anywhere; `main` stays on CPU 0), `thread_join` frees every kernel stack again (S06's `stack_cpus` is gone), `uthread_kill` and `uthread_interrupt` poke a thread running on another CPU with the wake IPI (`thread_poke`) so it enters the kernel at once, and the shim's console `write` takes kprintf's guard. ktests in suite `smp` (`ktest_tlb.c`): `smp_shootdown_protect` and `smp_shootdown_unmap` (a kernel thread on another CPU writes a page through `probe_write64` while main write-protects or unmaps it; afterwards the frame must not change and the writer must fault; with the remote flush skipped for that page the first fails at `*frame == v0`, and with no remote flush at all the suite crashes earlier on a reused kernel stack), `smp_user_threads_everywhere` (three ring-3 `jmp $` threads land on CPUs 1-3 and are each killed within 50 ms). `smoke.sh` takes `SMP=n`; `SMP=4 make go-smoke ports-smoke` pass (threads, gohello, forkbench, shmtest, waitstress), with the Go kernel's runtime still on one P.

### [ ] W20-S08 Go on N CPUs, budgets, M20 (E12)
`sched_getaffinity` reports the CPUs online (`nproc` and `sysconf` follow), so the Go kernel runs with that many Ps and the scheduler of goroutines spreads the dispatcher, the handlers and the drivers; `go test -race` of `kernel/...` stays clean on the host. `make smp-bench` (not in `make test`): a CPU-bound four-thread C program and a Go user program on 1 and 4 CPUs, `syslat` and the fork and net budgets on 4. Every smoke runs with `-smp 4` and multi-threaded TCG (`SMP ?= 4`, `SMP=1` for the old behaviour); docs: an "SMP" section in ARCHITECTURE.md, NUCLEUS_ABI.md's new calls if any, MEMORY_MAP.md's trampoline page.

Exit: **M20 demo — many CPUs, hardened.** `make test` green with `-smp 4` (and with `SMP=1`); `nproc` 4; the four-thread program at least 2.5 times faster than on one CPU; SMEP and SMAP on; ACPI poweroff; BUG-0023 closed or explained; DEVLOG wave entry.

Not in this wave: per-CPU run queues and load balancing, CPU affinity calls beyond what is reported, NUMA, CPU hot-plug, an I/O APIC for interrupts (the 8259 in virtual-wire mode keeps delivering to the BSP), a tickless timer, UEFI, virtio, real hardware.

Risks and pitfalls (PIT-NN entries go into BUGS_AND_MITIGATIONS.md when the wave starts):
- **Races that one CPU hid.** Code that relied on "interrupts off means alone" (the scheduler, the IRQ pending bits, `trap_last`, the uthread request FIFO, the futex table) is now wrong unless it also takes a lock; S05 lists every global the nucleus writes before S06 lets a second CPU run threads.
- **A lost wake-up across CPUs.** A thread that checks a condition and then blocks must do both under the lock its waker takes, or the wake-up lands in between (PIT-23's rule, now with a real second CPU); ktests ping-pong across CPUs millions of times.
- **Stale translations.** A CPU that still has an old TLB entry can write a page after it was write-protected or freed: copy-on-write breaks silently, a reused frame is corrupted. Shootdown before reuse, always; the ktests aim at exactly this.
- **The trampoline is sixteen-bit code in a page the loader must leave alone.** Its address goes into the memory map and MEMORY_MAP.md; the regression suite gets a case that corrupts it and must fail loudly.
- **XSAVE area size and alignment.** The area is CPUID-sized (up to a few KiB with AVX-512) and must be 64-byte aligned; a thread created from a frame (`clone`) copies it whole.
- **SMAP finds the nucleus touching user memory.** Each such access is either a bug or gets an explicit `stac`/`clac`; a ktest proves an unbracketed one faults.
- **Multi-threaded TCG changes timing everywhere.** Smoke tests with fixed waits may flake; every keys file waits for text, not time, and the budgets are measured again on four CPUs.
- **Go's runtime on many Ps.** More Ms in the nucleus at once, signals (`SIGURG` preemption by `tgkill`) aimed at threads running on other CPUs (an IPI must stop them at their next return), parallel GC; the census of runtime syscalls is rerun.
