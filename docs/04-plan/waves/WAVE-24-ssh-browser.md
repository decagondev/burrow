# W24 ssh, TLS and a Browser  (M24)  — status: in progress
Goal: Burrow is a machine you reach and work from over the network. Demo: the host's `ssh` logs in to Burrow through `hostfwd` with a password and with a key, runs a command, opens an interactive shell on a pseudo-terminal and copies a file with `scp`; inside Burrow, `dbclient` logs in to Burrow itself over loopback; busybox `wget` and `curl` fetch `https://` pages from the host and check the certificate; NetSurf, a graphical browser, renders a page with styles and images from the host in an X window, follows a link by a click and loads an `https://` page; `make ssh-smoke` and `make browser-smoke` pass; `make test` green. Stories: E21.F01-F05 ([BACKLOG.md](../BACKLOG.md)).

Where we start (after W23): the network is two cards (e1000, virtio-net) under gVisor's stack, with `AF_INET` sockets, names, DHCP, and servers inside Burrow reached through `hostfwd` (busybox `httpd`, `goserve`). TLS exists only for Go programs (`user/go/gofetch`, Go's own `crypto/tls` with built-in roots); busybox's `wget` is built without HTTPS, and no C program can speak TLS. There is no ssh at all. A multi-user Unix is in place for it: users and groups with `set*id` and set-id `execve`, `login`, `/etc/passwd` and `/etc/shadow` with busybox's SHA-512 `crypt`, pseudo-terminals with controlling terminals and job control, `/dev/urandom`, `/proc` (W23: `self/fd`, `ttyname`), `syslog`. The X desktop (W16) has Xlib, xcb, FreeType, fontconfig and zlib built static for musl (`scripts/x11.sh`); downloaded ports are pinned by sha256 and cached under `~/.cache/burrow-*` (`scripts/ports.sh`, `x11.sh`, `qt.sh`), and each port's system calls are taken from the host first (`make x11-census`, `qt-census`).

Design (ports, and the kernel only where a port shows a gap):
- **The census first, every time.** Each new program runs under `strace -f` on the host (as `x11-census` and `qt-census` do), the calls are compared with what `kernel/proc` serves (`TestCensus*`), and the gaps become kernel work in the slice that needs them, with a Go test, before the port boots on Burrow.
- **TLS for C programs is mbedTLS.** One small, static library (no OpenSSL); a CA bundle at `/etc/ssl/certs/ca-certificates.crt` on the ports disk, and the smokes' own CA for the host's test servers. busybox's `wget` gets HTTPS from its built-in TLS (`FEATURE_WGET_HTTPS`), `curl` from mbedTLS, so two independent TLS stacks check each other against the same server.
- **ssh is dropbear.** A small server and client (`dropbear`, `dbclient`, `dropbearkey`, `scp`), static against musl, with no PAM and no utmp: passwords are checked with `crypt` against `/etc/shadow`, keys against `~/.ssh/authorized_keys`, and a session gets a pseudo-terminal (`/dev/ptmx`), a login shell and the user's ids (`setgid`/`initgroups`/`setuid`). Host keys are made once by `dropbearkey` on the ext2 root (or a test disk), never shipped in the image. The server runs from the shell or from a start-up script; `hostfwd` forwards a host port to its port 22.
- **The browser is NetSurf.** A small graphical browser with its own HTML and CSS engines (libdom, libcss, hubbub), fetching through libcurl over mbedTLS, drawing through libnsfb onto an X window (xcb, already built) with FreeType text. It is the largest port so far after Qt, so it starts with a spike: if NetSurf's libraries do not build static for musl in a slice's worth of work, links2 in graphics mode on X is the fallback, and the wave says so.
- **Tests talk to real clients and servers.** The host's own OpenSSH client logs in to Burrow (a Python harness drives it, as `fetch.py` drives HTTP); `scp` copies a file both ways and the host checks it; `tls-server.py` (W17-S06) serves the host side of TLS with a test CA; NetSurf's window is checked by pixels, as X's other programs are.

### [x] W24-S02 dropbear: the host logs in (E21.F02)
dropbear built static (no PAM, no lastlog or utmp, `crypt` from musl), `dropbearkey` making ed25519 and RSA host keys at first start into `/etc/dropbear` on the ext2 root (`scripts/mkroot.py` makes the directory; the test root gets fresh keys per run). The census of a whole session on the host (dropbear on a high port, the host's ssh client). Kernel gaps found by the census are fixed here (expected: `getgroups`/`setgroups`/`initgroups` paths, `SO_KEEPALIVE` and `TCP_NODELAY` on inet sockets, `getsockname`/`getpeername` on accepted TCP sockets, `ioctl(TIOCSWINSZ)` on a pty from a non-controlling process). `tests/smoke/ssh.py` (Python's `subprocess` around the host's `ssh` with a throwaway known-hosts file): a password login (`sshpass` or an `SSH_ASKPASS` helper), a command (`id; ps`), and a key login with `authorized_keys`. `make ssh-smoke` (in `make test`, skips without `make busybox net-ports` or an ssh client on the host): go-unix.img on a test root with `hostfwd` to port 22.
As built: dropbear 2025.88 (pinned in `scripts/net-ports.sh`) as four static programs on the NETDATA disk (`dropbear`, `dbclient`, `dropbearkey`, `scp`: FAT holds no links for a multi-call binary), no PAM, login records or zlib; `user/net/localoptions.h` points `scp` at `/opt/net/bin/dbclient`, gives sessions `PATH=/bin:/opt/net/bin` and leaves out SFTP and X forwarding. Host keys: `dropbear -R` makes them at the first connection into `/etc/dropbear` (0700, made by `scripts/mkroot.py`, whose `/etc/profile` now adds `/opt/net/bin`); a fresh test root per run gives fresh keys. The census (`tests/regression/census-ssh.sh`, `make ssh-census`, `TestCensusSsh`) runs dropbear on the host as the user (its own host key, `-D` for the `authorized_keys` directory, which with every parent must not be writable by others, so it lives under `~/.cache/burrow-net`) and counts only dropbear's processes, its re-execution of itself included; the calls it makes only as root are listed by hand. It found two calls Burrow did not serve: `set_robust_list` (musl's `fork` calls it in every child; now recorded, `robust.go`; dead owners' robust futexes are not yet marked) and `execveat` (dropbear runs itself again per connection from its own descriptor with `AT_EMPTY_PATH`; `execat.go`, beside `execve`, now split into `execName`). A non-root dropbear's pty session is hung up by WSL's kernel as it opens the pty, so on the host that session only counts calls. And BUG-0030: the VFS could not walk to a mount under a directory the root lacks (`/opt/net` on the ext2 root); `vfs/virtual.go` makes such directories. `tests/smoke/ssh.py` drives the host's OpenSSH (an `SSH_ASKPASS` helper for passwords, a throwaway key and known-hosts file under `~/.cache/burrow-net`, as OpenSSH refuses a key `/mnt/c` shows as everyone's): burrow logs in by password, a key goes into `authorized_keys` over that login, a key login runs `id` and `ps`, a wrong password is refused. `make ssh-smoke` (in `make test`; skips without `make busybox ports net-ports` or an ssh client): go-unix.img on a copy of the test root, root starts dropbear on the console and waits for the report the host leaves in `/tmp`. Entropy (PIT-85): `kernel/random` is ChaCha8 seeded from RDRAND, which QEMU's CPU has (the boot logs `seeded from RDRAND`); host keys are made on the machine. That is enough for a test network, not a claim of cryptographic strength, as `kernel/random` says.

### [x] W24-S03 Interactive sessions, scp and dbclient (E21.F02, F03)
An interactive login through the host's `ssh -tt`: a shell prompt, `stty size` follows a window change (`SIGWINCH` through the pty), `^C` interrupts a foreground program, `exit` returns the host's ssh with the shell's status. `scp` both ways (a 1 MiB file, checked by sha256 on both sides). `dbclient` logs in from Burrow to Burrow over 127.0.0.1 as another user (a key from `dropbearkey -y`). Two sessions at once, each with its own pty and process group. `ssh-smoke` grows these; `make ssh-bench` (not in `make test`): login time and `scp` throughput, printed.
As built: `tests/smoke/sshterm.py` runs the host's `ssh -tt` on a host pseudo-terminal it owns (the size set before ssh starts, changed with `TIOCSWINSZ`, so ssh sends a window change as in a terminal window); `tests/smoke/sshchecks.py` opens two shells at once (different `/dev/pts/N`, process groups and sessions, read from `/proc/$$/stat`), checks `stty size` before and after a resize and a `WINCH` trap in a foreground `sh -c` (the signal goes to the foreground group, as on Linux), `^C` on a foreground `sleep` (status 130), `exit 7` returned by the host's ssh, and `scp -O` (OpenSSH's original protocol: dropbear has no SFTP) of 1 MiB each way, sha256 compared on both sides. On the console root makes a key with `dropbearkey`, adds `dropbearkey -y`'s public half to burrow's `authorized_keys`, logs in with `dbclient -y` over 127.0.0.1 and copies `/etc/passwd` with Burrow's own `scp` (which runs `dbclient`). dropbear now runs with `-F -E` in the background, its messages kept in `/tmp/dropbear.log` and printed. The sessions found three gaps: a pty's slave had no owner, so dropbear's `chown` of it to the user failed the session (`proc/ptyowner.go`: the opener's ids and mode 0620, as devpts; `chown`/`chmod` with the usual rules; stat and fstat both describe it from there); an `scp` of 1 MiB to the ext2 home wrote the whole file back for every KiB (`wfile` now writes back every change below 64 KiB, then at each doubling, at the last close and at `fsync`); and BUG-0031, `mkdir` of an existing name was `EACCES` rather than `EEXIST`, so busybox's `mkdir -p /root/.ssh` failed. `make ssh-bench` (`SSH_MODE=bench`, `expect/ssh-bench.txt`): about 1.7 s a key login and 0.9 MB/s `scp` of 4 MiB each way on TCG, printed; S06 budgets them.

Risks and pitfalls (PIT-NN entries go into BUGS_AND_MITIGATIONS.md when the wave starts):
- **Ports bring system calls nobody served yet.** dropbear and NetSurf are the first big network programs in C; the census on the host before each first boot turns each gap into a kernel slice with a test, never a surprise at the smoke.
- **ssh needs every piece of the Unix at once.** A login is `crypt`, shadow passwords, `setgroups`/`setgid`/`setuid` in the right order, a pty with a controlling terminal, a session leader and job control; one wrong id or a terminal that is not the controlling one breaks it quietly (the census and `credtest`'s rules guide it).
- **Entropy and keys.** Host keys and TLS need good random numbers: `kernel/random` is ChaCha8 seeded from RDRAND or the TSC and was "not for cryptography" (W14-S03); this wave either makes it fit (RDRAND required, reseeding, a test of its output's distribution) or says plainly that Burrow's ssh is for a test network. Host keys are made on the machine, never shipped.
- **TLS on TCG is slow.** Handshakes do big-number arithmetic under emulation; timeouts in the smokes and the tools (`curl --connect-timeout`, ssh's `ConnectTimeout`) must allow for it, and the budgets are measured before they are set.
- **NetSurf is big.** Many small libraries, a generated-code tool (nsgenbind) for the host, and a build system of its own; the spike has a budget and a fallback (links2) so the wave cannot stall on it.
- **Two TLS stacks, one test CA.** busybox's built-in TLS and mbedTLS differ in what they accept (cipher suites, TLS 1.3); `tls-server.py` must offer what both take, and a refusal must be checked as carefully as an acceptance.
