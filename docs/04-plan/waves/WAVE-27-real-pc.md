# W27 A Real PC's Devices  (M27)  — status: in progress
Goal: Burrow runs on the devices a real PC has, not only QEMU's legacy ones, and one USB stick carries all of it. Demo: QEMU's `q35` machine with OVMF, no IDE controller and no PS/2 devices, boots `build/burrow-usb.img` from a USB stick (`usb-storage` on QEMU's xHCI): interrupts come through the I/O APIC and MSI; the root, home, X and data volumes are found by label on the stick, on a SATA disk (AHCI) and on an NVMe disk; a USB keyboard and mouse drive the console, Doom and the desktop; the same image written to a real stick boots a real PC far enough to report what it found (on the screen, W26-S04); `make test` green. Stories: E24.F01-F05 ([BACKLOG.md](../BACKLOG.md)).

Where we start (after W26): the firmware path works (UEFI or BIOS), but the devices Burrow drives after it are QEMU's `pc` machine's: interrupts through the 8259 in virtual-wire mode (`nucleus/irq.c`, ADR-0005), disks on the IDE controller (`drivers/ata`) or virtio, a PS/2 keyboard and mouse (`drivers/ps2`), an e1000 or virtio-net. Real PCs of the last decade have none of the first three: devices interrupt through the I/O APIC or by message (MSI, MSI-X), disks are SATA behind AHCI or NVMe, and keyboards and mice are USB, behind xHCI. A stick Burrow boots from is itself a USB disk, so without USB storage the kernel cannot mount the volumes on it. ACPI's MADT, which the nucleus already parses for CPUs (W20-S04), also names the I/O APICs and the interrupt overrides.

Design (each device proved on QEMU first; the old paths stay for `pc`):
- **Interrupts the modern way.** The nucleus programs the I/O APIC from the MADT (its address, the global system interrupts, the ISA overrides such as the timer on GSI 2), masks the 8259, and routes each line to a vector `irq_wait` already knows; PCI devices get MSI or MSI-X vectors (`pci.Capabilities`, a nucleus call to allocate a vector), legacy INTx through the ACPI `_PRT` only if a device has nothing else. ADR-0005 is unchanged: an interrupt is a wake-up for one Go goroutine.
- **Disks: AHCI and NVMe.** `drivers/ahci` (a port's command list and FIS in DMA pages, READ/WRITE DMA EXT, NCQ later) and `drivers/nvme` (one admin and one I/O queue pair, MSI-X) register `block.Writer`s, named `sd*` and `nvme0n1`, mounted by label like `hd*` and `vd*`; `block/blocktest` conformance for both, host tests against fake controllers like `virtio/virtiotest`.
- **USB: xHCI, then HID and storage.** `kernel/usb` (pure: descriptors, the hub and port state machine, device enumeration, control/bulk/interrupt transfer requests) over `drivers/xhci` (rings in DMA pages, the event ring on an MSI vector, root ports); class drivers on top: HID boot protocol keyboards and mice into `evdev` and the console as the PS/2 ones feed them, and mass storage (bulk-only transport, SCSI READ(10)/WRITE(10)/READ CAPACITY) as `block.Writer`s named `ub*`. Hot-plug is enumeration on a port change; unplugging a mounted disk ends its I/O with errors, not a panic.
- **One stick holds everything.** `make uefi-usb` (W26-S05) already puts the volumes on one GPT disk; the kernel now reads partitions (GPT, and MBR for old data disks) on every block device and mounts them by label wherever they are.

### [x] W27-S01 The I/O APIC and MSI (E24.F01)
The nucleus finds the I/O APICs and overrides in the MADT (`acpi.c`), masks the 8259 and routes the ISA lines it uses (the PIT or LAPIC timer, keyboard, mouse, serial, RTC, the IDE lines) through the I/O APIC, falling back to virtual wire when the MADT has none; PCI MSI and MSI-X (`kernel/pci` capabilities, `nu_irq_alloc_msi`), used first by virtio and the e1000. ktests for the routing on `pc` and `q35`; `make test` unchanged on `pc`, and a `q35` boot of go.img in `make q35-smoke`.

As built: `acpi.c` reads the MADT's interrupt source overrides and the I/O APIC's first GSI; `nucleus/irqroute.c` (pure, `test_irqroute.c`) turns a line into its GSI, trigger and polarity (the override, else the ELCR for "conforms", a level line with no stated polarity active low) and builds redirection entries and MSI messages; `nucleus/ioapic.c` writes the entries. `irq.c` puts every ISA line on the I/O APIC when the MADT names one (kargs `irq=pic` keeps the 8259; LINT0 is masked), sends EOI to the LAPIC, and masks only level lines until the ack: the I/O APIC drops an edge on a masked pin (PIT-102). MSI lines 16-47 on vectors 0x50-0x6F come from `nu_irq_alloc_msi` (0x102E); `nu_irq_route` (0x102F) says where a line goes. QEMU's MADT puts the PIT on GSI 2 and its PCI lines 5, 9, 10, 11 level and active high, on `pc` and on `q35`. Go: `pci.Capabilities`, `EnableMSI`, `EnableMSIX` (pure, host-tested) and `pci.Setup`/`pci.Serve` (MSI-X, else MSI, else the INTx line through `driver.Lines`); `virtiopci` gives virtio devices MSI-X with one entry for the configuration and every queue (`virtio.Device.MSIX`; the ISR is not read then); the e1000 and the AC'97 have no MSI capability on QEMU and stay on INTx. `irqs` on the console lists each ISA line's route and each PCI line's interrupts. `tablet-smoke` boots its tablet with `vectors=0` so it still proves W22's shared line. `make q35-smoke` runs the irq ktests on `q35` with OVMF and boots go-uefi.img there (go.img's BIOS loader reads by IDE, which `q35` has not): the e1000's level line and virtio-blk's MSI-X both deliver; `make ktest` runs the irq suite once more with `irq=pic`.

### [x] W27-S02 AHCI and NVMe (E24.F02)
`drivers/ahci` and `drivers/nvme`, host-tested against fakes and `blocktest`; `disk-smoke` and `dev-smoke` halves with the data disk on `-device ahci` and `-device nvme`; `make disk-bench` gains both. Partition tables read on every block device (`kernel/block/part.go`: GPT with its CRCs, MBR), each partition a `block.Device` (`sda1`, `nvme0n1p1`) mounted by label.

As built: `drivers/ahci` (class 01.06.01, ABAR in BAR 5; each implemented port with a device is stopped, given a command list, FIS area and one command table in a DMA page, and started again: OVMF leaves the ports running; one command at a time in slot 0, up to 16 data pages, READ/WRITE DMA EXT and FLUSH CACHE EXT; IDENTIFY's model; `sda`, `sdb`, ... in port order) and `drivers/nvme` (class 01.08.02; reset, a polled admin queue, IDENTIFY with MDTS, one I/O queue pair of 64 entries on MSI-X with up to 8 commands in flight, PRP lists; `nvme0n1`, ...), both host-tested against fake controllers with `blocktest`. `kernel/block/part` reads a disk's volumes: a GPT (the EFI system partition left out, PIT-99), else a file system on the whole disk, else an MBR's primary partitions; names `sda1`, `nvme0n1p1`. `cmd/kernel/bootparts.go` finds the boot disk on any interface (`bootDisk`: Burrow's manifest at sector 1, or a GPT with an EFI system partition; IDE, then SATA, virtio, NVMe, USB) and mounts every other disk's volumes by label (`dataVolumes`). `DISK_IF=ahci|nvme` puts the smokes' data disks on a controller each (`ahci_drive`, `nvme_drive`), with expect files `virtio-expect.py --if` derives; `make storage-smoke` runs disk-smoke and dev-smoke on both, and `disk-bench` times all four interfaces. On `q35` the boot disk is the ICH9's AHCI `sda` (`boot_to_q35.txt`).

### [x] W27-S03 xHCI and USB keyboards and mice (E24.F03)
`drivers/xhci` and `kernel/usb` (enumeration, hubs, control and interrupt transfers), HID boot keyboards and mice into `evdev` and the console; `make usb-smoke` boots `q35` without PS/2 (`-device qemu-xhci -device usb-kbd -device usb-mouse`) and types the go-smoke session, then drives paint and X with the mouse; keys files work unchanged (QEMU's `sendkey` reaches the USB keyboard).

As built: `drivers/xhci` (class 0C.03.30): the controller taken from the firmware (USB legacy support, its SMIs off), reset, given its device context array (and scratchpad pages when it asks), a command ring and one event ring on interrupter 0, MSI-X where it has it; rings are one DMA page each closed by a Link TRB, a transfer descriptor never straddles it (`ring.go`, pure and host-tested); a command or control transfer also drains the event ring while it waits, so a lost interrupt costs time, not a hang. Each connected root-hub port is reset (USB 2; a USB 3 port is enabled by its link), its device given a slot and an address, endpoint 0's packet size corrected from the first 8 bytes of its descriptor, and its descriptors and configuration read (`port.go`); a stall resets the endpoint and moves its ring past the transfer (`device.go`). `kernel/usb` is the layer above: descriptors, `usb.Device` and `usb.Pipe`, and `Bind`, which sets the configuration and starts a class driver per interface. A HID boot keyboard's reports become scancode set 1 bytes (`hid.go`; Alt+PrintScreen is SysRq) fed to `Env.Scancodes` and through `ps2.Decoder` to the console, so `/dev/input/event0`, the VT keys and the hang dump work unchanged; a boot mouse's reports go to `Env.Mouse` (`event1`, `/dev/input/mice`). A USB keyboard repeats nothing by itself, and neither does this. No external hubs (QEMU's devices sit on the root hub). `make usb-smoke` boots go-uefi.img on `q35,i8042=off` with `qemu-xhci`, `usb-kbd` and `usb-mouse` (on QEMU's USB 2 ports 5 and 6, high speed): a console and sh session with Ctrl-C and shifted characters, mousetest and paint's pixels; then `usb-smoke-x11` runs x11-smoke's keys and expect file unchanged on go-dev-uefi.img with the X disk on virtio: xhello, st, dwm and Doom from dmenu through the USB devices.

### [x] W27-S04 USB storage (E24.F04)
Bulk-only mass storage over `kernel/usb` (`ub*` devices, SCSI commands, a stall or reset recovered, a removed stick failing its I/O); `make usb-smoke` also mounts a data disk on `-device usb-storage` and runs dev-smoke's edit, compile and reboot on it.

As built: `kernel/usb/storage.go` and `bot.go`: an interface of class 08.06.50 (SCSI over the bulk-only transport) is opened on its bulk IN and OUT pipes, asked INQUIRY (its model), TEST UNIT READY until it is ready (REQUEST SENSE between, up to 5 s) and READ CAPACITY(10), and registered as `uba`, `ubb`, ... (`Bind`); reads and writes go in READ(10)/WRITE(10) commands of up to 64 KiB, each data stage in page-sized transfers; `Flush` is SYNCHRONIZE CACHE (a refusal is no error). A stalled data stage ends it: the endpoint is reset on the host (`xhci`) and cleared on the device (CLEAR_FEATURE ENDPOINT_HALT) and the status wrapper still read; a status wrapper that is not valid, or a phase error, gets the reset recovery. Host-tested against a fake stick over a RAM disk: `blocktest`, writes across commands, a stall, a removed stick. `DISK_IF=usb` puts the smokes' data disks on usb-storage behind an xHCI controller each (`usb_drive`; `virtio-expect.py --if usb`). `usb-smoke-storage` (in `make usb-smoke`) runs disk-smoke and dev-smoke on them, then boots go.img with its data disk on a stick, reads it, pulls it out with the keys file's new `monitor device_del` step, and checks that the next read fails with an error (after the bulk transfer's 10 s timeout) and the kernel runs programs on. QEMU's usb-storage is a super-speed device on the first USB 3 port.

### [x] W27-S05 One stick, on q35 and on a real PC (E24.F05)
`build/burrow-usb.img` boots on `q35` + OVMF from `usb-storage` alone: the root, home, X and net volumes on the stick, the desktop as burrow (the unix-desktop demo), `make usb-desktop-smoke`. A first-boot report on the screen and in `/var/log/hw.txt` (what the kernel found: CPUs, the interrupt controller, every PCI device with its driver or none, the disks and partitions, the USB devices), so a tester sends one photo or one file. `make usb-initrd` writes a smaller image that needs no disk driver at all (the console, busybox and Doom in the initrd) for a first "does it boot" try. REAL_HARDWARE.md updated: what to try first, what to send back.

As built: `make usb-desktop-smoke` boots `build/burrow-usb.img` on `q35,i8042=off` with OVMF from a usb-storage stick alone (`smoke.sh`'s `BOOT_IF=usb`) and a USB keyboard and mouse (`unix-desktop.sh`'s `QEMU_MORE`): the stick is `uba`, its root, net and X partitions `uba2`-`uba4`, and the unix-desktop session runs as before, checked over ssh. `cmd/kernel/hwreport.go` writes the hardware report once the disks are mounted: the firmware, the CPUs, the interrupt controller, every PCI function with the driver that claimed it (`pci.Setup` claims for the driver its `env.Log` names, `klog.Logger.Subsystem`; bga claims its own) or "no driver", the USB controllers and devices (`usb.Notes`, ports that failed included), the disks, the mounts and every interrupt line's count; in `/var/log/hw.txt`, or `/tmp/hw.txt` on a read-only root, printed by the console's `hw`, and on the screen at boot with kargs `hwreport`. `make usb-initrd` writes `build/burrow-initrd-usb.img` (about 100 MiB): only the boot partition, sized by `uefi_image`'s new third argument, whose initrd holds busybox, Doom and the Freedoom WAD at `/opt/doom`, with kargs `hwreport`; `usb-desktop-smoke`'s first half boots it the same way: the report, busybox, Doom's title. An MBR's EFI system partition (type 0xEF) is skipped like GPT's. REAL_HARDWARE.md now starts with the initrd stick and asks for a photo of the report or the file.

Risks and pitfalls (PIT-NN entries go into BUGS_AND_MITIGATIONS.md when the wave starts):
- **Interrupt routing differs per machine.** ISA overrides, active-low and level-triggered lines, PCI pins behind bridges; QEMU's `q35` covers the common case only. MSI first everywhere it exists, and the routing table printed at boot so a real machine's report shows it.
- **DMA and caches on real controllers.** QEMU forgives a missing barrier or a buffer above 4 GiB that a 32-bit-only controller cannot reach; DMA pages come from below 4 GiB unless the controller says it can do 64 bits.
- **xHCI is a big specification.** Rings, cycle bits, contexts, port resets and timeouts; build only what HID and storage need, host-test the pure parts, and stop on the first controller error with its state printed.
- **USB timing is real time.** Port resets and device settle times are milliseconds the Go kernel must actually wait; QEMU is lenient, real devices are not.
- **A real PC is tested by someone else.** No serial port, no debugger: the screen report (W26-S04, S05 here) is the only evidence, so every failure must say where it stopped.
